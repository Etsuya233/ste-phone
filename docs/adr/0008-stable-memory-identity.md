# Phone 使用 Memory 稳定身份保存资料关联

状态：接受。2026-11-01。补充 ADR 0002 的资料身份约定。

Memory 导入和分支克隆会重新分配空间、表、字段与记录 ID，并重映射内部引用。Phone 保存的日记作者包含旧空间与人物 ID，导入后无法继续读取该作者的资料。

Memory 维护 `space.stableId` 和 `record.stableId`，导出、导入和分支克隆保留它们。旧快照先按原空间与记录 ID 初始化稳定身份，再进入克隆流程。新建记录拥有新稳定身份；改名和内容更新保留身份。同一空间实例内的稳定记录身份跨表唯一，不同分支可保留相同身份及不同内容。

Phone 要求 `STE_MEMORY_API.identity.version === 1`，通过 `database.describe().space.stableId` 和公开业务系统列 `$stable_id` 建立标准视图的 `stable_scope_id/stable_record_id`。原 `scope_id/record_id` 继续表达实例身份，Memory API 请求、缓存、视图注册、聊天切换和迟到响应检查仍使用当前实例归属。

日记作者现有 `scopeId/id` 字段分别映射稳定空间与人物身份，不更改日记 v1 的存储结构，不批量迁移 Phone 数据。旧快照稳定身份与原 ID 相同，已有作者引用可以直接使用。生成时先核对稳定空间，在当前人物视图中按稳定记录身份找到本地记录，再用该本地记录 ID 查询关联纪要。作者姓名保留展示及历史署名职责，不参与自动匹配。

能力缺失、人物已删除或稳定空间不匹配时明确报错，已保存日记仍可阅读。旧版导入已经丢失对应关系的数据无法仅凭当前内容自动恢复，本次不增加人工重新绑定或会话合并流程。两个扩展继续独立构建，Phone 只依赖公开协议，不导入 Memory 仓库源码。
