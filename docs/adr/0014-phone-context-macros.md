# 手机 App 提供同步上下文来源，ST 宏引用聊天预设

状态：由 [0015](0015-app-intents-and-st-bindings.md) 调整配置所有权，实时同步读取原则继续沿用。2026-11-12。

用户需要把选定人物之间的近期手机内容放入 ST 提示词。首版范围为微信，人物集合匹配会话双方，支持现实分钟窗口和每会话条数；后续应用需要独立接入。ST 新宏处理函数同步执行，当前微信记录已保存在 ST 页面聊天元数据，无需网络预加载。

`core/phone-context/public.ts` 定义同步 `ContextSource` 契约，包括候选空间与人物、选择校验、带固定当前时刻的读取和结果统计。App 实现自己的筛选与格式规则；微信直接消费 `WechatStorage.read`，不依赖微信页面、当前帐号或异步 Memory 人物读取。来源通过 bootstrap 显式注入，Core 不导入 App，不建立全局服务查找器。

`apps/phone-context` 拥有版本化的命名预设、保存生命周期、预览与展开。预设按 ST 聊天保存到 `chatMetadata.ste_phone.contextPresets`，复用宿主元数据写队列；宏标识创建后固定。每次展开重新读取预设和来源，窗口以该次同步读取时刻计算，没有文本缓存、已消费游标或异步预加载。一次展开内部时间固定，分别发生的 token 计算、预览和生成展开可反映新保存的内容。

微信先匹配稳定资料空间及双方人物，再应用生效屏障、现实时间区间及最近条数。撤回正文不输出，表情文字化，消息仍按保存顺序排列；消息文本、姓名以引用格式转义，防止关闭标签或在后续替换中执行宏。结果携带会话数、消息数与排除计数。无匹配内容返回空文本，非法数据或不可用来源明确报错。

基础设施通过 ST 的 `macros.register` 注册 `{{phone::预设标识}}`，只调用同步展开。注册失败显示通知和日志且保留手机主体功能；读取失败同时返回明确错误文本，避免宿主吞下异常后只保留无法解释的原宏。新宏引擎必须持续开启，首版不兼容旧引擎语法。

代价：读取与格式化随每次展开执行，大历史下可能增加主线程工作；仅当前页面已同步并已确认保存的记录可见。首版来源契约抽取人物、空间、时间和分组数量这些共同筛选维度；后续 App 若需要不同筛选能力，应扩展明确的来源配置契约，避免把 App 专有规则堆到宏适配器。现阶段不增加通用模板语言、自动摘要和跨浏览器同步。

该决策延续 0006 的 App 数据所有权及公开接口边界、0008 的稳定身份和 0009 的版本化存储约定。
