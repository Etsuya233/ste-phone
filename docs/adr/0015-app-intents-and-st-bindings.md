# 应用拥有 App Intent，ST 接入只绑定宏

状态：接受，2026-11-12。

0014 将人物、时间和条数配置统一放在全局上下文预设中。不同应用的读取规则会有明显差异，用户要求将配置放回应用，并把微信入口命名为「App Intent」。全局设置仅负责 ST 接入与宏标识。

微信拥有自己的命名 Intent、选择结构、校验、存储端口、生命周期和页面。入口位于「微信 → 我 → 设置 → App Intent」，保留人物集合、现实时间、每会话条数与排除统计预览。Intent 使用独立稳定 ID，名称可修改，删除时说明已有宏引用会失效。

`core/phone-context/public.ts` 只声明 `AppIntentSource`：应用标识、显示名、按聊天列出已保存的 Intent 摘要，以及按聊天、Intent ID 与固定当前时刻同步读取文本。人物、资料空间、时间窗口和统计均归微信模块。新 App 可提供完全不同的配置，无需扩展宏层的选择结构。

全局 `PhoneContextService` 拥有 v2 宏绑定 `{id,name,sourceId,intentId}`，在「设置 → ST 接入」配置。展开时读取当前已保存绑定，并调用该 App 的同步来源接口；配置编辑与异步初始化不进入展开路径。绑定与 Intent 不自动级联删除，失效引用明确报错，用户可以重新绑定。所有服务由 bootstrap 显式组装，应用页面关闭不影响读取。

旧 v1 预设按原标识拆成同 ID 的微信 Intent 和原宏绑定。读取时纯投影，首次显式保存时原子提交两份迁移数据，不在宏展开中保存。微信 Intent 与微信消息分块存储，避免消息的全量保存覆盖 Intent。迁移后删除 Intent 不会从旧记录重新恢复，失败保留旧结构供重试；未知来源或冲突数据明确报错。

本决策替代 0014 的通用选择结构和全局配置界面，保留已确认保存数据、同步实时读取、聊天隔离和错误可见的规则。
