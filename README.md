# STE-PHONE

面向 SillyTavern 的小手机插件。使用 React、TypeScript、普通 CSS 和 esbuild，提供 iPhone 6s 风格外壳、主屏幕、秒表、Foundation 组件、只读资料应用、Fake DBeaver 数据库应用、日志查看和壁纸设置。公共数据源连接 STE Memory，将 Phone 定义的标准视图注册到 Memory 已提交数据库，供当前人物、纪要、物品和世界状态查询。

「微信」以当前 Memory 人物作为帐号，首次打开选择人物；其余人物默认进入通讯录。「微信 / 通讯录 / 我」提供会话列表、人物资料及帐号切换，同一对人物共享双向单聊，切换帐号后按人物身份改变消息方向。已有 v4 桌面配置保留原布局，可从 App Store 获取微信；新配置默认安装。

微信支持「立即发送」和默认的「延迟发送」，可在「我 → 发送模式」切换，偏好跨聊天保存。「发送」始终提交已有队列与输入框内容并触发 AI 回复。延迟模式下发送按钮为白色，右侧显示绿色「队列」文字按钮，点击将当前输入保存为一条消息、清空输入框，可连续加入多条文字和表情；立即模式使用绿色发送按钮，隐藏队列按钮。空输入也可以发送：有队列时回复队列，没有待回复消息时让对方结合背景主动开口，不创建空白用户消息。待回复消息按聊天、单聊与发言人物保存，刷新或切帐号后仍可继续；切模式不自动触发。AI 生成时当前聊天顶栏以「用户正在输入...」替换联系人名称，发送按钮变为停止，输入框仍可编辑。停止丢弃本次整批回复、保留用户消息与草稿；若回复已进入保存阶段，则等待原目标的撤回保存确认后恢复发送，撤回失败明确报错。一次回复可拆成多条文本。取材包括双方完整资料、全部剧情大总结与未总结纪要、任一方关联的人际关系、当前持有物品及重要事件，以及关系和事件直接涉及的第三人简介；仅按明确人物引用取一跳，不递归扩展，也不把相关背景当作角色已经知情。关系保留双方各自态度，物品持有不推断所有权，未来、延期、取消和已结束的重要事件均保留。另附最近清洗后的 10 条 ST 消息及本单聊最近 N 条消息（默认 100，可在「微信 → 我 → 设置」修改），连续发送超过窗口时完整保留本轮待回复消息，不额外调用模型压缩。资料页的「剧情总结」展示相同 summary；总结和关联映射按需检查，缺少映射时明确报错。生成失败可重试回复，避免重复发送；保存失败直接显示错误。Home 和关闭手机继续生成，切帐号、切 ST 聊天或 Expose 退出微信取消。消息与帐号按 ST 聊天保存，不回写 ST 正文或 Memory。

微信聊天顶栏「···」和消息本身可在首条前、消息之间或末尾插入「记忆屏障」，点击消息打开操作菜单；拖动选字、双击或三击选词、复制文字时不会触发。屏障固定在所选消息边界，支持独立开关与删除。聊天中以分隔条呈现，生效屏障用绿色标出 AI 读取起点和排除条数，关闭或已被接管的屏障显示为灰色虚线；点击屏障标签打开操作菜单，在菜单内开关或删除。多道开启时，最新一道生效，AI 只读取它之后的微信消息，用户仍可阅读完整聊天。屏障后再应用设置的最近 N 条窗口，获准的本轮待回复消息完整保留，可超过 N；屏障前的旧队列在生成成功后视为跳过，关闭屏障也不会自动重发。失败或停止保留原队列，重试按当时屏障重新取材。人物资料、剧情背景和最近 ST 消息继续提供。屏障按 ST 聊天、双人单聊保存，双方帐号共用；回复或保存期间暂不能修改，生成中可先停止。只有屏障的空会话可从通讯录进入，首次发消息后出现在会话列表。

「微信 → 我 → 设置」提供「AI历史消息条数」，须为正安全整数，默认 100，双方每条文本或表情各计一条，时间分隔和屏障不计数。显式保存后跨帐号和聊天共用，从下一次生成或手动重试生效；当前请求固定原值，修改不触发回复。保存失败保留草稿与原配置，未保存返回可继续编辑或舍弃。

微信人物资料页（含「我 → 个人资料」）提供「回复指导」，可填写表达习惯、话题限制或性格表现，显式保存后从下一次生成生效，失败重试读取最新保存内容。指导按当前 ST 聊天、稳定空间与人物身份保存，同一人物在不同微信帐号视角下共享；清空并保存恢复默认。指导仅传给当前回复人物，独立于背景材料作为系统指令，保留剧情事实、人物知情范围、现实时间、JSON 格式及可用表情限制。生成中修改不影响本轮，指导与消息依次保存以避免互相覆盖；旧 v1 数据未填写时沿用默认表现。

微信按设备本地时区显示现实发送时间：首条消息、跨天或相邻消息间隔超过 5 分钟时显示时间分隔；会话列表显示最后消息时间，并按最近消息倒序。旧消息沿用已保存的 `createdAt`，无需迁移。AI 同时获得历史发送时刻、相邻消息间隔、本轮之前的交流间隔及当前现实时间；延迟队列和主动开口也保留时间语境。现实间隔只影响微信话题衔接，不能推进剧情世界时间、推断角色作息或编造期间发生的事，剧情相对日期与事件进展仍以世界状态和剧情资料为准。

独立预览 `/?wechat=1` 进入微信，使用设置中的模拟模型连接；`wechat-test=slow/error/length/invalid/save-error` 分别模拟慢回复、请求失败、截断、非法 JSON 与保存失败。预览消息独立保存在 localStorage，刷新后恢复，不请求真实模型。

微信「我 → 表情包」右上角「＋」可导入 st-emote 导出的 ZIP（`st-emote-pack` v1，包含 `st-emote.json` 与图片）。支持 PNG、JPEG、WebP、GIF，单图最大 5 MB，GIF 原样保存；外链保留地址。导入后默认开启，同名包、缺文件或非法清单明确报错，不覆盖已有包。每个包可单独开关；已开启且有标签和图片的表情出现在聊天输入框旁的笑脸面板中，点击保存并按当前发送模式决定是否触发对方回复，保留已有文字草稿。AI 从本轮已开启的表情清单中按标签和描述选择，可混合发送多条文字和独立表情。

表情消息沿用文本存储，原文为 `[[sticker:包名:标签]]`，一条消息完整匹配才显示图片。关闭包后历史消息显示原始标记，重新开启立即恢复图片；未导入或无法匹配的标记也保留原文。开关不改写历史，下一轮 AI 只看到开启的包。表情库按 ST 账号跨聊天保存，元数据位于 `extensionSettings.ste_phone_wechat_stickers`，包内图片通过 ST 原生接口保存到 `user/images/ste-phone-stickers/`，不依赖安装 st-emote。独立预览使用自己的 localStorage 和 IndexedDB，刷新后恢复图片与开关。首期提供导入、预览和开关，编辑表情仍在 st-emote 中完成。

`/?wechat=1&data-state=related` 使用稳定身份与实例身份不同的关联样例，包含双方持有物品、不同态度的人际关系、延期与已结束事件，以及直接相关的同名第三人；一跳以外的记录用于检查排除行为。模拟回复固定，实际取材内容由 SQL 与提示词集成测试验证。

「日记」打开后先展示一本本大封面，左右滑动切换书目，第一本是「大家的日记」，其余按 Memory 人物成书；人物书按最后一条日记的实际写入时间倒序，没写过的书排在后面。点封面进入这本书的页面，再点击条目阅读。写作时执笔人跟随当前这本书，在「大家的日记」里落笔则沿用上一次的执笔人。生成会以当前执笔人的第一人称，结合世界状态、最近 5 条关联且已结束的纪要和最近 20 条清洗后的聊天。最近聊天需要同轮更新的 STE Memory 提供 `STE_MEMORY_API.chat v1`，缺少能力时明确报错；Phone 不直接读取 ST 原文。使用 Phone 默认模型连接，生成设置默认总超时 300 秒、输出上限 10240 token，篇幅由模型自然发挥。完整生成后自动保存，可回看，右上角菜单提供复制、删除或再写一篇。执笔人、生成设置和日记按聊天保存在聊天元数据中，已保存内容可在 Memory 或模型不可用时阅读。

生成中 Home 和关闭手机继续运行，Expose 明确退出或切换聊天取消；资料普通更新不重算本次生成。取消、错误和输出截断不保存半篇；保存失败保留完整正文供复制或重新保存。保存通过 ST 单聊/群聊原生保存接口发送已固定目标的聊天快照，保留完整性检查，不强制覆盖。分支继承 ST 当时复制的元数据，旧日记不按楼层回退。

独立预览 `/?diary=1` 可直接进入日记书目；模型连接需在预览设置中添加，所有回复均为模拟且不请求真实模型。`diary-test=slow/error/length/save-error` 分别检查取消、生成错误、输出截断和保存失败；`diary-test=demo` 在没有已保存日记时展示多本书与样例版式。预览日记独立存于 localStorage，刷新后保留。

日记生成在同一轮返回正文与配图描述，描述随日记保存，阅读页正文与配图分开展示。写作设置中的「完成后自动生成配图」默认关闭，开启后先保存日记，再交给 Image Hub 自动匹配参考图并生成；每篇日记关联一张图片，后端返回多张时关联第一张，其余仍保留在 Hub 图库。配图以相纸样式附在日记页，点开可查看大图，并可更换配图、调整描述或移除；选图会先预览再确认，当前配图在图库网格中带「当前」标记，替换前有明确提示。移除只解除这一页的关联，图片文件和配图描述都保留，可以再次生成。图片文件归 Image Hub，日记只保存图片 ID 与路径，删除日记不会删除图库图片。

配图失败保留正文和描述；关联保存失败时图片已留在图库，可重新选取；移除失败保留现有配图并显示错误。Home 和关闭手机继续处理；切换聊天或明确退出日记后停止本地关联，已经提交到 Image Hub 的任务仍可能生成并保存图片。配图期间日记内其他写入操作暂不可用，不增加任务排队或跨聊天恢复。

「图库」展示 ST Image Hub 已保存的图片，首次打开读取，右上角「刷新」重新载入且保留当前网格；从其他应用或 Home 回到图库时静默重读。图片按今天、昨天、更早分组，点缩略图进入可左右滑动、方向键翻页的大图，显示描述、保存时间并可复制描述；空图库可直接前往图乐园。「图乐园」把描述便签固定在底部，Enter 生成、Shift+Enter 换行；本次结果以相纸落在上方画布，成功后合并进「最近作品」，可用「再画一张」复用本次提交的描述，参考图由 Hub 自动匹配。两应用通过 `ST_IMAGE_HUB_API v1` 接入，需要安装并启用 ST Image Hub；缺失或版本不兼容会在操作时提示，不影响其他手机应用。生成与保存由 Hub 负责，不写 ST 聊天正文。Home、关闭手机和退出应用都让 Hub 继续生成；退出后回到图库会自动读取新结果。已有桌面布局可从 App Store 获取两个应用。

独立预览 `/?gallery=1`、`/?image-playground=1` 分别进入图库与图乐园，使用本地模拟图片和生成，不请求真实模型。`image-test=empty/error/missing/slow` 分别展示空图库、读取与生成失败、Hub 未安装和慢生成；生成结果仅保留在预览内存中，刷新重置。

## 安装与运行要求

当前版本：**0.0.5**。资料与数据库功能需要 **[STE Memory](https://github.com/Etsuya233/ste-memory) 0.2.6 或更新版本**，该版本提供 `STE_MEMORY_API.database v1` 与日记所需的 `STE_MEMORY_API.chat v1`。请先安装或升级 Memory，再刷新 ST。未连接 Memory 时，手机外壳、秒表及组件应用仍可使用。

本轮源码还要求 Memory 提供 `identity v1` 稳定身份能力，请配套更新两个插件。空间导出导入和分支继承会保留人物等资料的稳定身份，当前实例 ID 仍可改变。Phone 的日记存储格式保持 v1，已有作者引用无需改写；Memory 旧快照升级时使用原空间与记录 ID 初始化稳定身份。旧版导入已经遗失的身份对应关系无法自动恢复。缺少稳定身份能力时明确提示升级，已保存日记仍可阅读。

在 SillyTavern「扩展 → 安装扩展」中填写：

| 插件               | 仓库 URL                                  | Branch or tag name           |
| ------------------ | ----------------------------------------- | ---------------------------- |
| STE Memory ≥ 0.2.6 | `https://github.com/Etsuya233/ste-memory` | `release/sillytavern-plugin` |
| STE Phone 0.0.5    | `https://github.com/Etsuya233/ste-phone`  | `release/sillytavern-plugin` |

安装后刷新页面，从聊天输入区的**魔法棒菜单 → 小手机**打开。更新使用 ST 扩展面板的 Update；升级 Phone 前请核对本节所需的 Memory 最低版本。`main` 分支用于源码开发，ST 安装请选择上述构建产物分支。

## 开始

使用 mise 固定 Node.js 与 pnpm 版本，不依赖 Corepack。

```sh
mise install
pnpm install --frozen-lockfile
pnpm preview:frontend
```

预览默认监听 `0.0.0.0:18826`，本机打开 `http://127.0.0.1:18826/`；同一局域网的设备使用终端输出的本机 IPv4 地址访问，例如 `http://192.168.1.10:18826/`。修改代码后刷新页面。可通过环境变量 `PORT` 改端口，`HOST` 改监听地址；只需本机访问时设置 `HOST=127.0.0.1`。

手机默认保持完整 iPhone 6s 机身比例，桌面和移动端均等比缩放至可用视口。`PhoneApp` 保留可选的全屏响应式模式和拖拽能力，默认关闭，也不显示操作柄。开发预览可通过 `?responsive=1` 开启窄屏全屏模式、`?draggable=1` 开启顶部机身拖拽，两项可组合；生产入口不读取这些参数。

打开手机后，点击主屏的「组件」（Foundation）图标进入组件应用，可操作导航栏、按钮、分组列表、开关、分段控件和页面滚动示例；导航示例包含列表、详情与下一层，返回保留滚动位置和控件状态；组件应用不连接或保存 ST 数据。开发预览也可用 `/?foundation=1` 快捷进入，可与上述参数组合；普通入口默认进入主屏。

主屏长按图标或按 F2 进入编辑，拖动调整顺序，也可在主屏与 Dock 之间移动；Dock 最多四个图标。点击主屏空白处、按 Home 或 Escape 退出，方向键支持排序，Ctrl + 上/下方向键移入主屏/Dock。资料、设置与 App Store 不可卸载，其余应用点 × 确认卸载，运行中的页面会退出，已保存的业务数据保留。App Store 提供应用列表与搜索，点「获取」重新安装到主屏末尾，已安装应用可直接打开。布局与安装状态跨聊天保存，刷新后恢复；独立预览可用 `/?app-store=1` 进入商店。

Home 单击返回主屏，双击进入 Expose。已打开的 App 保留页面与状态，后台以 iOS 7 风格的横向页面预览显示，中央卡片与相邻卡片沿用各 App 的真实页面，下面是主屏同款图标和应用名称。界面只保留壁纸、卡片和图标，不显示额外入口、页码或提示。左右拖动或按方向键选卡，点击卡片/图标或 Enter 打开；上滑或 Delete 关闭应用，退出动画完成后卸载页面。关闭手机后重新打开回到原前台页，刷新 ST 会结束内存会话。秒表退到后台继续计时，仅在前台刷新显示。资料按聊天与范围重置导航栈，数据库工作区继续按聊天保留。

「设置 → 壁纸」显示默认渐变和 Phone 上传的图片，使用三列 9:16 缩略图。右上角「+」上传 PNG、JPEG 或 WebP（最大 10 MB），上传后进入全幅预览；选择 Blur 后点「设定」保存并返回图库。上传图片通过 ST 原生图片接口保存到 `data/<账号>/user/images/ste-phone-wallpapers/`，配置只保存所选路径与 Blur，图片内容留在账号目录，不改变 ST 背景。全局设置通过 `extensionSettings.ste_phone` 交给宿主延迟保存。

设置 schema 为 v6，包含壁纸、模型连接、微信发送模式、AI 历史消息条数、主屏与 Dock 排列，排列中的应用即已安装应用。v5 及更早配置升级后将 AI 历史消息条数设为 100，保留已有有效设置。v4 配置升级时保留原配置并将微信发送模式设为延迟发送；v3 配置升级时保留壁纸和连接，并添加默认布局与 App Store。首次读取 v1 时移除旧 URL 列表与旧背景选择，恢复默认渐变并保留 Blur；v2 保留壁纸与 Blur，补上空连接列表和未选择的默认连接。独立预览使用自己的 IndexedDB 保存 Blob、localStorage 保存配置，刷新时重新生成图片 URL；不连接真实 ST。`/?settings=1` 可快捷进入设置，同一局域网 HTTP 预览也支持上传。

「设置 → 模型连接」支持添加、编辑和删除命名连接，配置 OpenAI Chat Completions 兼容服务的 Base URL、API Key、模型 ID 与自定义请求头。Base URL 需要包含服务要求的路径前缀（如 `/v1`），不要填写完整 `/chat/completions` 地址。首个连接保存后自动设为默认，点击连接行选择默认，左侧勾选标记表示当前选择，右侧圆圈 i 进入编辑；也可选择「无默认」，删除默认连接后清空选择。保存显式提交草稿，返回时可确认舍弃；Home 与关闭手机保留草稿，Expose 退出设置或刷新结束草稿。

测试进度、模型回复和失败信息显示在手机内的 iOS 风格弹窗。运行中可取消，失败后可重试；「好」或 Escape 关闭弹窗，关闭运行中的弹窗会取消测试。Home 与关闭手机保留运行及弹窗状态，返回设置后继续查看。

模型请求在浏览器开发者工具 Console 中记录 `[STE Phone AI]` 日志，以 `requestId` 串联请求、HTTP 响应、完成或失败，并标注「日记生成」「微信回复」或「连接测试」。请求日志的 `input` 保存交给 ST 代理的完整协议载荷，包含系统提示词、消息历史、工具定义和生成参数，鉴权字段在发送时单独加入。结束日志集中保存同一份 `input` 与 Pi assistant 消息 `output`，可一起复制排查；输出包含正文、模型返回的思考、工具调用与结束原因，截断、流中断、超时和取消也保留已收到的部分内容。`complete` 表示本次模型传输结束，应用后续的回复解析和保存仍可能失败。错误保留完整 HTTP 响应体、上游 SSE 错误、原始异常与原因链，不截断、不做密钥脱敏；同时写入 Pi 原生 diagnostics，应用包装错误时继续保留这些诊断。失败提示给出对应请求编号。

「日志」应用在手机内展示 Phone 自己的运行日志，当前包括启动信息和上述 AI 请求事件。每条日志记录时间、级别、来源应用、消息和完整详情，可筛选级别与应用、查看结构化文本并复制。最近 1000 条写入浏览器 LocalStorage（`ste-phone-logs-v1`），刷新后恢复；日志不做脱敏，也不按 ST 聊天区分，卸载应用不会清除已保存记录。独立预览可用 `/?logs=1` 直接进入。

共享传输支持工具定义、工具调用增量、工具结果回传和 Pi Agent 的多轮工具循环；模型思考转换为独立 thinking 内容块。工具注册、思考展示及业务结果要求由应用决定。日记和连接测试目前不注册工具，收到意外工具调用由各应用终止，不触发后续模型请求；两者只提取最终文本，思考不展示、不保存为正文。只有思考而无正文由应用报空回复，输出截断保持各应用原有处理。

连接测试使用当前填写的配置，通过 Pi Agent 和 ST 同源 Custom 代理发送一次简短文本生成，支持流式、取消和 60 秒超时，可能产生少量用量；保存配置不会自动测试。首期仅验证文本生成，未接入业务生成或工具调用。API Key 可以留空，自定义 `Authorization` 优先于 API Key；无鉴权时显式使用空值，避免继承 ST Custom 连接的密钥。请求头名不区分大小写且不能重复，值可为空但不能含换行；`Content-Type` 固定 JSON，传输层请求头不可自定义。API Key 和请求头值明文保存在 Phone 的 ST 设置中，界面默认隐藏，不改变 ST 主连接或密钥。

独立预览的模型测试始终模拟，不联系配置的服务，回复中明确标记模拟结果；`model-test=slow`、`error`、`length` 可分别验收取消、失败与输出上限状态，例如 `/?settings=1&model-test=slow`。Pi 两包锁定 `0.83.0`。生产与预览共用设置模块的 Agent、提示词、输出限制与超时流程，预览仅替换为模拟 AI 传输；生产协议转换位于宿主适配器。

## 开发命令

主屏「资料」可以查看 STE Memory 的当前背景资料、搜索和复制正文。需要同时安装支持 `STE_MEMORY_API v1` 和 `database v1` capability 的 Memory 构建，展示映射支持「剧情记忆」预设；结构不符会明确提示。主屏「数据库」（Fake DBeaver）提供对象搜索、列与关联说明、只读 SQL 和结果复制，提供 `src_*` 源别名及 `phone_*` 标准视图。标准世界时间用 `SELECT date(world_time) FROM phone_world_state;` 查询。公共缓存跨 App 保留，刷新 ST 后重建视图连接，不写回 Memory；SQL 草稿、结果、搜索和滚动位置按聊天及资料范围保留在内存。独立预览使用示例数据，可用 `/?data-source=1` 或 `/?database=1` 快捷进入，加入 `data-state=empty`、`error`、`unavailable`、`unsupported` 检查状态。接口、映射和缓存说明见 [公共数据源](docs/data-source.md)。

```sh
pnpm build             # JS、CSS、manifest；清理旧 Worker/WASM
pnpm watch             # 增量构建；配置 .env 后自动同步到 ST
pnpm preview:frontend  # 独立预览，共用生产组件与 CSS
pnpm typecheck
pnpm lint
pnpm format:check
pnpm test              # 串行验证工程接入、资料缓存、远端查询与标准视图 SQL
```

生产入口为 `src/frontend/index.ts`，与独立预览共用 `src/bootstrap/create-phone.tsx` 组装设置、资料、数据库工作区与应用页面，入口分别注入宿主或模拟适配器。`src/apps/<应用>/` 集中各应用业务与 `ui/` 页面；`src/frontend/host/mount-phone.tsx` 挂载 React 与 Shadow DOM，`phone-app.tsx` 管理窗口开关。`frontend/device/` 放机身与会话，`frontend/system/` 放状态栏与转场，`frontend/foundation/` 放基础视觉组件，`frontend/apps/home/` 放主屏，`NavigationStack` 提供保留 DOM 的页内导航，`frontend/theme.css` 汇总 CSS 与主题变量。React 随插件打包。手机外壳使用 Inter 并优先使用 Apple 平台字体；日记界面使用 Noto Serif SC 衬线体，正文使用 LXGW WenKai 手写体。字体由挂载入口通过 Google Fonts 与 jsDelivr 声明，不进入产物；网络不可用时回退到 Georgia、楷体或本机衬线字体。构建产物的 manifest 版本与运行时版本统一读取 `package.json`。

全局设置与存储约定位于 `src/apps/settings/`，`public.ts` 提供壁纸读取、模型连接摘要与显式连接配置副本。公共资料、查询结构与来源缓存归 `src/apps/data-source/`，通过 `DataAppPublic` 供其他应用读取；`src/apps/database/` 只持有 SQL 草稿、结果、搜索与滚动等编辑工作区。Memory 数据库连接、协议和视图定义位于 `src/infrastructure/ste-memory/`，ST 设置、图片、AI 传输与聊天通知适配位于 `src/infrastructure/host/`；`src/core/ai/` 和 `src/core/chat/` 声明传输及当前聊天契约。各应用公开读取不依赖页面打开，跨应用仅通过所属模块的 `public.ts` 调用。职责与依赖见 [模块架构](docs/architecture.md)，资料接口与缓存见 [公共数据源](docs/data-source.md)。

## ST 安装与开发直连

将 `.env.example` 复制为 `.env`，配置 `STE_ST_INSTALL` 或 `STE_ST_EXTENSION_DIR`，两者选一。相对路径以本仓库为基准。`.env` 不进入 Git。

推荐通过 Junction 让 ST 直接读取 `dist/`：

```sh
pnpm build
pnpm st:link
pnpm watch
```

`STE_ST_INSTALL` 自动推导目标目录 `public/scripts/extensions/third-party/ste-phone`。Windows 创建 Junction，其他平台创建目录符号链接。链接指向当前工作区的构建产物；修改后需刷新 ST 页面，入口为右下角“手机”按钮。

```sh
pnpm st:unlink         # 仅解除当前 dist 对应的链接，保留 dist 内容
```

目标若已存在真实目录、指向其他位置的链接或断链，命令报错并保留原内容。Worktree 开发前核对链接指向，避免构建目录与 ST 加载目录不一致。

也可以使用拷贝部署：

```sh
pnpm deploy:st         # 生产构建，再拷贝三个发布文件并清理旧 Worker/WASM
pnpm sync              # 单独同步已有构建产物
```

`watch` 没有配置目标时仅构建；配置后在构建成功时同步。目标已直连当前 `dist` 时跳过拷贝。修改 `package.json` 后重启 watch。

## 发版

发布分支为 `release/sillytavern-plugin`，分支根目录仅放插件产物和安装说明。源码在正常开发分支维护，发版命令不会切换当前工作区的分支。

先更新 `package.json` 与源码 `manifest.json` 的版本，执行检查并提交源码，然后运行：

```sh
pnpm release:st --dry-run # 构建验证，允许源码未提交，不修改发布分支
pnpm release:st           # 离线生成或更新本地发布分支并提交
pnpm release:st --push    # 生成并推送 origin 的发布分支
```

发版 worktree 固定在主仓库 `.worktrees/release/sillytavern-plugin/`。命令拒绝未提交的源码、未提交的发布内容，以及发布分支中的非产物文件；推送使用普通 Git push，不强制覆盖远端历史。重复运行相同版本和源提交不会新增提交。

公开仓库为 [Etsuya233/ste-phone](https://github.com/Etsuya233/ste-phone)，ST 安装分支为 `release/sillytavern-plugin`。发布分支 README 同步注明最低 Memory 版本，后续通过扩展面板的 Update 更新。

## 微信朋友圈

从「微信 → 发现 → 朋友圈」阅读动态，点击「发布」以当前帐号分享文字、1—9 张图片描述或单条视频描述。媒体暂以带类型标识的描述文字占位，允许仅媒体，图片与视频不能混用。点击动态阅读全部内容和评论，可发表评论或回复某条评论；评论平铺显示。切帐号后共享同一范围的历史，各帐号只能删除自己的动态和评论；删除原评论后，其他人的回复保留并注明原评论已删除。

「AI 发布动态」先选择发布人物，完整生成一条后直接保存；「AI 生成互动」为当前动态生成 0—5 条评论，可让人物互相回复，排除当前操作帐号。两者复用 Phone 默认模型连接，手动发布、评论、阅读和刷新不调用模型。AI 取材使用人物资料、各自回复指导、剧情总结、世界状态与最近清洗后的 10 条 ST 消息；发布另取单人关联背景及该人物最近 10 条动态，互动取目标动态及最近 50 条评论和直接回复目标。不读取微信私聊，也不回写 ST 正文或 Memory。

朋友圈按 ST 聊天与稳定资料空间保存，切换帐号只改变操作身份。人物离开或资料不可用时，已保存内容仍可只读查看。Home、关闭手机和普通返回继续生成；切帐号、聊天、资料实例或 Expose 退出微信取消。微信同时最多一项 AI 任务，生成失败或输出不合法不保存半批；AI 保存失败直接报错，可显式重新生成，手动保存失败保留草稿。不增加跨标签同步、冲突合并或后台恢复。

独立预览使用 `/?wechat=1&moments-test=demo` 展示媒体、评论和历史人物样例；`moments-test=empty/slow/error/invalid/length/save-error` 分别模拟空互动、慢生成、请求错误、非法 JSON、截断和保存失败。预览复用生产取材与协议，仅返回模拟内容，不请求真实模型；默认模型连接仍需在预览设置中配置。

### 互动参与人物

点击「AI 生成互动」后，可勾选最多 5 位人物，再点「生成互动」。每位选中人物至少回复一条，整批最多 5 条，未选人物不会发言；不勾选或点击「清空选择」时，由 AI 自行挑选，也可能无人回应。当前微信帐号不参与 AI 代写。模型遗漏选中人物时整批报错，不保存部分评论；页面保留选择供重试。选择仅用于本次操作，Home 和关闭手机保留，重新进入选择页恢复默认自动模式。
