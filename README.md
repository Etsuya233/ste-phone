# STE-PHONE

「浏览器」可选一位当前 Memory 人物创作网页。作品打开后先显示可交互预览，底部可进入「创作对话」「源码」「版本」。源码页可编辑标题及 `index.html`、`style.css`、`script.js`；下一轮创作可通过工具按需读取当前三个文件，包含手动修改。浏览器从「设置」里已有的模型连接中单独选择并跨聊天记忆，所选连接删除后需要重选。每轮开始时固定连接配置。所选模型接口需支持 OpenAI Chat Completions 的原生工具调用。

预览顶栏的「全屏」在手机内保留顶栏和网页，隐藏地址状态栏与底部操作区；点击「还原」返回普通预览。切换保留同一个网页实例和运行进度。创作对话复用地图公共过程组件，展示当前作品最近一轮的思考与运行状态，可展开查看；只显示模型接口实际返回的思考，没有思考内容时不显示思考步骤。过程在本次页面会话内保留，不写入作品版本。过程按实际发生顺序展示思考、文件工具调用的参数与结果，以及角色的过程说明。

角色通过 `read_file` 读取、`write_file` 完整写入、`edit_file` 精确替换当前作品的三个文件，工具按顺序执行。编辑原文不存在或匹配多处时返回明确错误，角色可继续读取和修正。每轮使用独立源码副本，工具修改期间不更新页面；模型正常结束并返回文字回复后整批更新草稿，点预览右上角「保存」才把作者、标题、创作对话和源码写入当前 ST 聊天，并新增保存版本。停止、请求失败或输出截断会保留原源码与本次指令；保存失败可直接重试。恢复旧版会把标题和源码复制到草稿并保留创作对话，显式保存后形成新版本。返回列表、Home、关闭手机和 Expose 退出时，未保存草稿在当前页面会话内保留，列表提供「舍弃草稿」。Home 和关闭手机继续生成，Expose 退出、切 ST 聊天或切 Memory 资料实例会停止生成；已经提交的保存仍归发起时的聊天。已有作品可在 Memory 不可用时预览和编辑，继续生成需要原作者在当前资料中可用。

工具仅访问 `index.html`、`style.css`、`script.js`。`read_file` 可用从 1 开始、包含两端的行范围读取，保留原始换行；`write_file` 可附带作品标题。每轮先发送人物资料、文件目录、创作对话和本次要求，源码通过工具按需读取。浏览器不设置运行超时、模型轮数或工具调用次数上限，用户可随时停止；单次模型回复沿用 32768 token 的输出参数，截断会结束整轮并保留原稿。

作品以 iframe 运行普通 HTML、CSS 和 JavaScript，沿用宿主页面来源，首版无额外权限控制或 npm 构建。已有桌面可从 App Store 安装，新桌面默认提供入口。独立预览 `/?browser=1&responsive=1` 提供模拟连接，请在浏览器内明确选择；`browser-test=demo` 展示可点击的样例，`slow`、`error`、`length`、`invalid`、`save-error`、`slow-save` 模拟生成和保存状态。独立预览使用本地数据，不请求真实模型。

「微信 → 我 → 设置 → App Intent」管理微信自己的读取方案：填写方案名称，选择资料空间和至少两位人物，设置现实时间窗口与每会话条数，并预览实际读取内容。只有参与双方都被选中的单聊会进入结果，与手机当前操作帐号无关。候选人物取自该聊天已保存的微信会话和帐号；尚未出现的人物需先保存微信消息，再重新进入配置页。

「设置 → ST 接入」只管理宏与 App Intent 的绑定。新建绑定，选择应用及已保存的 App Intent，定义固定宏标识，再复制 `{{phone::wechat_recent}}` 形式的宏放入 ST 支持宏替换的提示词字段。微信方案使用独立稳定 ID；修改名称和读取条件后，引用该方案的宏自动采用最新保存内容。删除方案前会提示引用影响，绑定保留并明确报告引用失效。方案和宏绑定均按 ST 聊天保存。

微信 App Intent 默认读取最近 30 个现实分钟、每个会话最多 50 条，也可不限时间。展开时同步读取当前 ST 页面中已确认保存的记录，依次应用记忆屏障、现实时间范围和每会话条数限制，按会话分组并保留消息先后顺序。撤回只输出提示，表情输出文字，已保存的待回复消息标记待回复，草稿和生成中回复不进入结果。手机关闭或切换微信帐号不影响宏；正在保存时仍读取上次保存成功的内容。时间窗口随每次展开重新计算，无符合记录时返回空文本。

微信内「预览展开内容」按编辑草稿显示会话数、消息数及排除计数；全局宏预览读取所引用的已保存 Intent。刷新重新读取，预览不保存配置、不消耗消息。保存失败保留草稿，可重试；返回时可确认舍弃修改。旧版「ST 上下文」预设自动读取为微信 App Intent 和同名宏绑定，保留原宏文本；读取不写回，下次显式保存配置时一并持久化迁移结果。

宏使用 ST 新宏 API，需支持 `getContext().macros.register` 并保持 Experimental Macro Engine 开启；本机 ST 1.18.0 已验证，启用后请刷新 ST。能力缺失或读取失败会提示并记录日志，读取失败同时输出明确错误文本。宏不能直接刷新其他浏览器或服务端尚未同步到当前页面的数据。

独立预览 `/?wechat=1&phone-context-test=demo&responsive=1` 提供四位人物的微信样例，已有预览微信数据不会被覆盖；将 `wechat=1` 改为 `settings=1` 可进入全局设置。`phone-context-test=save-error` 模拟首次保存失败后重试，`slow-save` 模拟慢保存。方案与绑定使用独立 localStorage，样例时间只在首次创建时固定，刷新后自然经过时间窗口。

「声乐园」可以输入台词、生成配音、试听和下载 MP3。在「设置 → 语音连接」填写完整的 OpenAI Compatible Speech 地址、模型和音色列表，设定默认音色、合成语速、播放速度、音量及变速时是否保留音高。应用内可覆盖这些声音参数并恢复默认。音色和合成语速用于下一次生成，播放选项即时应用于试听。现有桌面从 App Store 安装，新桌面默认提供入口。

声乐园从浏览器直连 Speech 接口，跨域时由接口网关允许 CORS。使用 Realtime 适配器时填入 HTTPS Speech 地址、`gpt-realtime-2.1-mini` 和独立的 `BRIDGE_TOKEN`。默认与临时朗读风格通过 `instructions` 发送，由支持该字段的服务应用。独立预览 `/?voice-playground=1` 使用模拟音频。

「设置 → 外观」可分别选择手机外形（iPhone 6s / iPhone 17）与系统风格（经典 iOS / iOS 26），支持四种自由组合，选择后立即应用并跨聊天保存。旧配置升级后保留经典 iPhone 6s；切换外观保留应用页面、草稿和后台任务。iPhone 17 使用全面屏、灵动岛与底部 Home 条；从条快速上滑松手返回主屏，上滑减速定住后松手或按住停留约 240ms 查看后台，锁屏时上滑解锁。iPhone 6s 亮起锁屏后长按 Home 600ms 解锁。交互跟随手机外形，iOS 26 风格提供大圆角分组、胶囊控件、顶部渐隐导航、无边框模糊 Dock。

面向 SillyTavern 的小手机插件。使用 React、TypeScript、普通 CSS 和 esbuild，提供 iPhone 6s / iPhone 17 风格外壳、主屏幕、秒表、Foundation 组件、资料应用、Fake DBeaver 数据库应用、日志查看和壁纸设置。公共数据源连接 STE Memory，将 Phone 定义的标准视图注册到 Memory 已提交数据库，供当前人物、纪要、物品和世界状态查询。

点击右侧机身电源键锁屏，两种机型的响应式模式也保留侧电源键；iPhone 6s 响应式模式还可使用底部锁形按钮，iPhone 17 底部只保留 Home 条。关闭按钮位于顶部。锁屏先熄灭屏幕，点击黑屏、电源键或短按 Home 只唤醒到锁屏；iPhone 17 上滑解锁，iPhone 6s 长按实体或软件 Home 600ms 解锁。键盘可在 iPhone 17 锁屏按 Enter 或空格解锁；iPhone 6s 聚焦 Home 后按住 Enter 或空格 600ms 解锁，提前松开会取消。关闭重开保留锁屏状态、应用草稿和后台任务，刷新后重新开始手机会话；当前不设密码或自动熄屏。

「微信」以当前 Memory 人物作为帐号，首次打开选择人物；其余人物默认进入通讯录。「微信 / 通讯录 / 我」提供会话列表、人物资料及帐号切换，同一对人物共享双向单聊，切换帐号后按人物身份改变消息方向。已有 v4 桌面配置保留原布局，可从 App Store 获取微信；新配置默认安装。

微信支持「立即发送」和默认的「延迟发送」，可在「我 → 发送模式」切换，偏好跨聊天保存。「发送」始终提交已有队列与输入框内容并触发 AI 回复。延迟模式下发送按钮为白色，右侧显示绿色「队列」文字按钮，点击将当前输入保存为一条消息、清空输入框，可连续加入多条文字和表情；立即模式使用绿色发送按钮，隐藏队列按钮。空输入也可以发送：有队列时回复队列，没有待回复消息时让对方结合背景主动开口，不创建空白用户消息。待回复消息按聊天、单聊与发言人物保存，刷新或切帐号后仍可继续；切模式不自动触发。AI 生成时当前聊天顶栏以「用户正在输入...」替换联系人名称，发送按钮变为停止，输入框仍可编辑。停止丢弃本次整批生成的回复，保留用户消息与草稿。进入保存阶段后显示「正在保存回复…」，暂停发送且无法停止，直至原聊天保存成功或报错。一次回复可拆成多条文本。取材包括双方完整资料、全部剧情大总结与未总结纪要、任一方关联的人际关系、当前持有物品及重要事件，以及关系和事件直接涉及的第三人简介；仅按明确人物引用取一跳，不递归扩展，也不把相关背景当作角色已经知情。关系保留双方各自态度，物品持有不推断所有权，未来、延期、取消和已结束的重要事件均保留。另附最近清洗后的 10 条 ST 消息及本单聊最近 N 条消息（默认 100，可在「微信 → 我 → 设置」修改），连续发送超过窗口时完整保留本轮待回复消息，不额外调用模型压缩。资料页的「剧情总结」展示相同 summary；总结和关联映射按需检查，缺少映射时明确报错。生成失败可重试回复，避免重复发送；保存失败直接显示错误。Home 和关闭手机继续生成。切帐号、切 ST 聊天或从 Expose 退出微信可取消生成。保存期间暂停切帐号，切 ST 聊天或退出微信后仍保存到原聊天。消息与帐号按 ST 聊天保存，不回写 ST 正文或 Memory。

微信聊天顶栏「···」和消息本身可在首条前、消息之间或末尾插入「记忆屏障」，点击消息打开操作菜单；拖动选字、双击或三击选词、复制文字时不会触发。屏障固定在所选消息边界，支持独立开关与删除。聊天中以分隔条呈现，生效屏障用绿色标出 AI 读取起点和排除条数，关闭或已被接管的屏障显示为灰色虚线；点击屏障标签打开操作菜单，在菜单内开关或删除。多道开启时，最新一道生效，AI 只读取它之后的微信消息，用户仍可阅读完整聊天。屏障后再应用设置的最近 N 条窗口，获准的本轮待回复消息完整保留，可超过 N；屏障前的旧队列在生成成功后视为跳过，关闭屏障也不会自动重发。失败或停止保留原队列，重试按当时屏障重新取材。人物资料、剧情背景和最近 ST 消息继续提供。屏障按 ST 聊天、双人单聊保存，双方帐号共用；回复或保存期间暂不能修改，生成中可先停止。只有屏障的空会话可从通讯录进入，首次发消息后出现在会话列表。

点击单聊消息可撤回自己发出的消息，或确认删除任意一方的消息。撤回后在原位置显示提示，原文字或表情以 50% 不透明度显示。本人可取消撤回，恢复原内容及尚未完成的待回复消息。在屏障与历史窗口允许读取时，AI 只收到撤回提示，原内容不再作为待回复输入。删除从双方共享的单聊移除整条消息，保留已有回复、其余待回复消息和记忆屏障的分界。生成或保存期间暂不可修改，保存失败保留原消息。微信数据 v3 增加撤回状态，旧记录读取后沿用原内容，下次保存才写入新版本。

「微信 → 我 → 设置」提供「AI历史消息条数」，须为正安全整数，默认 100，双方每条文本或表情各计一条，时间分隔和屏障不计数。显式保存后跨帐号和聊天共用，从下一次生成或手动重试生效；当前请求固定原值，修改不触发回复。保存失败保留草稿与原配置，未保存返回可继续编辑或舍弃。

微信人物资料页（含「我 → 个人资料」）提供「回复指导」，可填写表达习惯、话题限制或性格表现，显式保存后从下一次生成生效，失败重试读取最新保存内容。指导按当前 ST 聊天、稳定空间与人物身份保存，同一人物在不同微信帐号视角下共享；清空并保存恢复默认。指导仅传给当前回复人物，独立于背景材料作为系统指令，保留剧情事实、人物知情范围、现实时间、JSON 格式及可用表情限制。生成中修改不影响本轮，指导与消息依次保存以避免互相覆盖；旧 v1 数据未填写时沿用默认表现。

微信按设备本地时区显示现实发送时间：首条消息、跨天或相邻消息间隔超过 5 分钟时显示时间分隔；会话列表显示最后消息时间，并按最近消息倒序。旧消息沿用已保存的 `createdAt`，无需迁移。AI 同时获得历史发送时刻、相邻消息间隔、本轮之前的交流间隔及当前现实时间；延迟队列和主动开口也保留时间语境。现实间隔只影响微信话题衔接，不能推进剧情世界时间、推断角色作息或编造期间发生的事，剧情相对日期与事件进展仍以世界状态和剧情资料为准。

独立预览 `/?wechat=1` 进入微信，使用设置中的模拟模型连接；`wechat-test=slow/error/length/invalid/save-error` 分别模拟慢回复、请求失败、截断、非法 JSON 与保存失败。`wechat-test=slow-save` 可检查保存期间的界面。预览消息独立保存在 localStorage，刷新后恢复，不请求真实模型。

微信「我 → 表情包」右上角「＋」可导入 st-emote 导出的 ZIP（`st-emote-pack` v1，包含 `st-emote.json` 与图片）。支持 PNG、JPEG、WebP、GIF，单图最大 5 MB，GIF 原样保存；外链保留地址。导入后默认开启，同名包、缺文件或非法清单明确报错，不覆盖已有包。每个包可单独开关；已开启且有标签和图片的表情出现在聊天输入框旁的笑脸面板中，点击保存并按当前发送模式决定是否触发对方回复，保留已有文字草稿。AI 从本轮已开启的表情清单中按标签和描述选择，可混合发送多条文字和独立表情。

表情消息沿用文本存储，原文为 `[[sticker:包名:标签]]`，一条消息完整匹配才显示图片。关闭包后历史消息显示原始标记，重新开启立即恢复图片；未导入或无法匹配的标记也保留原文。开关不改写历史，下一轮 AI 只看到开启的包。表情库按 ST 账号跨聊天保存，元数据位于 `extensionSettings.ste_phone_wechat_stickers`，包内图片通过 ST 原生接口保存到 `user/images/ste-phone-stickers/`，不依赖安装 st-emote。独立预览使用自己的 localStorage 和 IndexedDB，刷新后恢复图片与开关。首期提供导入、预览和开关，编辑表情仍在 st-emote 中完成。

`/?wechat=1&data-state=related` 使用稳定身份与实例身份不同的关联样例，包含双方持有物品、不同态度的人际关系、延期与已结束事件，以及直接相关的同名第三人；一跳以外的记录用于检查排除行为。模拟回复固定，实际取材内容由 SQL 与提示词集成测试验证。

「日记」打开后先展示一本本大封面，左右滑动切换书目，第一本是「大家的日记」，其余按 Memory 人物成书；人物书按最后一条日记的实际写入时间倒序，没写过的书排在后面。点封面进入这本书的页面，再点击条目阅读。写作时执笔人跟随当前这本书，在「大家的日记」里落笔则沿用上一次的执笔人。生成会以当前执笔人的第一人称，结合世界状态、最近 5 条关联且已结束的纪要和最近 20 条清洗后的聊天。最近聊天需要同轮更新的 STE Memory 提供 `STE_MEMORY_API.chat v1`，缺少能力时明确报错；Phone 不直接读取 ST 原文。使用 Phone 默认模型连接，生成设置默认总超时 300 秒、输出上限 10240 token，篇幅由模型自然发挥。完整生成后自动保存，可回看，右上角菜单提供复制、删除或再写一篇。执笔人、生成设置和日记按聊天保存在聊天元数据中，已保存内容可在 Memory 或模型不可用时阅读。

生成中 Home 和关闭手机继续运行，Expose 明确退出或切换聊天取消；资料普通更新不重算本次生成。取消、错误和输出截断不保存半篇；保存失败保留完整正文供复制或重新保存。保存通过 ST 单聊/群聊原生保存接口发送已固定目标的聊天快照，保留完整性检查，不强制覆盖。分支继承 ST 当时复制的元数据，旧日记不按楼层回退。

独立预览 `/?diary=1` 可直接进入日记书目；模型连接需在预览设置中添加，所有回复均为模拟且不请求真实模型。`diary-test=slow/error/length/save-error` 分别检查取消、生成错误、输出截断和保存失败；`diary-test=demo` 在没有已保存日记时展示多本书与样例版式。预览日记独立存于 localStorage，刷新后保留。

日记生成在同一轮返回正文与配图描述，描述随日记保存，阅读页正文与配图分开展示。写作设置中的「完成后自动生成配图」默认关闭，开启后先保存日记，再交给 Image Hub 自动匹配参考图并生成；每篇日记关联一张图片，后端返回多张时关联第一张，其余仍保留在 Hub 图库。配图以相纸样式附在日记页，点开可查看大图，并可更换配图、调整描述或移除；选图会先预览再确认，当前配图在图库网格中带「当前」标记，替换前有明确提示。移除只解除这一页的关联，图片文件和配图描述都保留，可以再次生成。图片文件归各自图库来源，日记只保存来源、图片 ID 与路径，删除日记不会删除图库图片。

配图失败保留正文和描述；关联保存失败时图片已留在图库，可重新选取；移除失败保留现有配图并显示错误。Home 和关闭手机继续处理；切换聊天或明确退出日记后停止本地关联，已经提交到 Image Hub 的任务仍可能生成并保存图片。配图期间日记内其他写入操作暂不可用，不增加任务排队或跨聊天恢复。

「备忘录」按角色显示、搜索和新建笔记，重新打开时恢复上次选择的角色。正文支持连续编辑和从图库插入图片，首个非空文字行作为标题，点「完成」或返回列表时保存。角色沿用 Memory 的稳定身份；已保存的笔记可在 Memory 不可用时阅读和编辑。笔记和上次选择保存在当前 ST 登录账号的 `user/files/ste-phone-notes.json`，切换聊天仍可访问，新桌面默认提供入口，已有桌面可从 App Store 获取。

「AI 新建」和「AI 写作」使用 Phone 默认模型连接，只发送本次指令。生成和候选预览期间正文只读，采用后恢复编辑；对已有笔记，文字插在发起时的光标处。独立预览 `/?notes=1&notes-test=demo` 提供两位角色的样例和模拟模型；`slow`、`error`、`length`、`save-error` 分别验收慢生成、生成失败、截断和保存失败后重试。

「图库」默认显示全部图片，可切换「手机图库」和「Image Hub」。右上角「＋」可多选 PNG、JPEG、WebP，单张最多 10 MB，保存前会检查文件内容并实际解码。上传固定进入手机图库，按照片文件和信息都保存成功的张数更新进度。Home、关闭手机和离开图库后仍继续；可在上传窗口取消，已经保存的照片会保留。部分失败时可只重试失败项。手机图库按 ST 登录帐号跨聊天保存，无需安装 Image Hub；其中一个来源读取失败时，另一个来源仍可浏览。

图库按今天、昨天、更早分组，点缩略图可左右滑动或用方向键翻阅大图，查看来源、保存时间并复制已有描述。右上角「刷新」重新读取，从后台回来时也会重读。日记、朋友圈、Twitter 配图、账号头像及资料中的人物通用头像均可从图库选图。

「图乐园」把描述便签固定在底部，Enter 生成、Shift+Enter 换行；本次结果以相纸落在上方画布，成功后合并进「最近作品」，可用「再画一张」复用本次描述。生成与保存由 ST Image Hub 负责，需要启用 `ST_IMAGE_HUB_API v1`。Home、关闭手机和退出应用都让 Hub 继续生成；回到图库后自动读取新结果。已有桌面布局可从 App Store 获取图库和图乐园。

独立预览 `/?gallery=1`、`/?image-playground=1` 分别打开图库与图乐园，使用本地模拟 Hub。手机图库在 IndexedDB 中保存，刷新后恢复；模拟 Hub 的生成结果刷新重置。`image-test=empty/error/missing/slow` 可检查 Hub 空数据、失败、缺失和慢生成；`photo-test=slow/index-error/refresh-error` 可检查慢保存、重试和刷新失败。

「Twitter」提供首页、关注和账号主页。同一剧情人物可有多个独立账号，社区也支持路人和公共账号。可手动发布文字或最多 9 张图片、关注、点赞、评论与楼内回复。图片可以先用描述占位、从图库选取或主动生成。背景热度与实际互动分开保存，未加载评论只显示数字。AI 发帖直接决定背景点赞数和评论数，普通人物日常默认两项为 0，新闻等公共内容按受众与传播程度生成；程序校验非负安全整数后原样保存。手动新帖默认零背景热度，已有帖子保持原值。

首页顶部常驻当前账号，点按进入「切换账号」，生成中切换会先确认停止当前任务。「关注」没有内容时展示推荐账号。信息流按头像左置展示，图片按数量选择单图、双图或三列布局；点赞和评论使用图标计数，相对时间随前台分钟更新，评论保存本地发送时间。帖子详情把背景热度与删除收进 `···`，生成评论留在评论标题旁，新增评论会定位并短暂标出。

发布页以三列网格管理最多 9 张配图，同一时间只展开一张图片编辑器，可填写描述、Prompt、选图、生成和调整顺序。返回或取消时检查未保存内容并确认舍弃；发布成功后回到信息流，标出新帖。图片加载失败时显示占位，不出现浏览器裂图。

「Twitter → 管理账号 → 批量创建角色账号」列出当前 Memory 资料空间的全部人物，默认不选，支持多选、全选、取消全选和按姓名搜索。按人物原名创建公开账号；已有公开账号（含已停用）的人物标注「已有账号」并禁选，只有小号的人物可补建。同名人物显示稳定身份，已有账号与当前操作身份保留。整批一次保存，失败保留选择，可重试；以后新增人物可再次进入补齐，不调用 AI。

账号资料页的头像可从图库选择，也可以清除；已有头像地址继续显示，加载失败时回退到昵称首字和稳定底色。

「AI 发帖」和「AI 生成评论」使用 Phone 默认模型连接，可自动选账号，也可限定候选账号，当前操作账号可以参与。指定账号时按剧情人物、路人和公共账号分组并支持搜索。生成完成后整批保存并自动回到新内容；模型失败或停止不写入数据。Home 和关闭手机保留任务与草稿，退出应用或切换账号、聊天、资料实例会停止尚在生成的任务。进入保存后继续写原聊天；失败可重试保存或舍弃，重试沿用原批次。外部切换 ST 聊天或资料后，可回原范围重试；退出社区前须先处理待保存批次。社区数据按 ST 聊天和 Memory 稳定资料空间保存。

新桌面默认安装，已有桌面可从 App Store 获取。独立预览用 `/?twitter=1`，`campus-test=empty/slow/error/invalid/length/save-error/slow-save` 可验收空数据、慢生成、生成异常与保存重试。预览用本地数据和模拟模型。

## 开始

使用 mise 固定 Node.js 与 pnpm 版本，不依赖 Corepack。

```sh
mise install
pnpm install --frozen-lockfile
pnpm preview:frontend
```

预览默认监听 `0.0.0.0:18826`，本机打开 `http://127.0.0.1:18826/`；同一局域网的设备使用终端输出的本机 IPv4 地址访问，例如 `http://192.168.1.10:18826/`。修改代码后刷新页面。可通过环境变量 `PORT` 改端口，`HOST` 改监听地址；只需本机访问时设置 `HOST=127.0.0.1`。

手机按所选机型保持完整机身比例，默认 iPhone 6s，桌面和移动端均等比缩放至可用视口。`PhoneApp` 保留可选的全屏响应式模式和拖拽能力，默认关闭，也不显示操作柄。开发预览可通过 `?responsive=1` 开启窄屏全屏模式、`?draggable=1` 开启顶部机身拖拽，两项可组合；生产入口不读取这些参数。

打开手机后，点击主屏的「组件」（Foundation）图标进入组件应用，可操作导航栏、按钮、分组列表、开关、分段控件和页面滚动示例；导航示例包含列表、详情与下一层，返回保留滚动位置和控件状态；组件应用不连接或保存 ST 数据。开发预览也可用 `/?foundation=1` 快捷进入，可与上述参数组合；普通入口默认进入主屏。

主屏长按图标或按 F2 进入编辑，拖动调整顺序，也可在主屏与 Dock 之间移动；Dock 最多四个图标。点击主屏空白处、按 Home 或 Escape 退出，方向键支持排序，Ctrl + 上/下方向键移入主屏/Dock。资料、设置与 App Store 不可卸载，其余应用点 × 确认卸载，运行中的页面会退出，已保存的业务数据保留。App Store 提供应用列表与搜索，点「获取」重新安装到主屏末尾，已安装应用可直接打开。布局与安装状态跨聊天保存，刷新后恢复；独立预览可用 `/?app-store=1` 进入商店。

iPhone 6s 在解锁后单击 Home 返回主屏、双击进入 Expose；iPhone 17 从 Home 条快速上滑松手返回主屏，上滑减速定住后松手或按住停留约 240ms 进入 Expose；聚焦 Home 条后也可用 Enter 或空格单次返回、连续两次查看后台。已打开的 App 保留页面与状态，后台随系统风格切换：经典风格使用横向页面预览，图标和名称位于下方；iOS 26 使用大圆角叠放卡片、上方图标与当前应用名称，背景为模糊主屏。两种布局均沿用各 App 的真实页面。界面只保留背景、卡片和图标，不显示额外入口、页码或提示。左右拖动或按方向键选卡，点击卡片/图标或 Enter 打开；上滑或 Delete 关闭应用，退出动画完成后卸载页面。关闭手机后重新打开回到原前台页，刷新 ST 会结束内存会话。秒表退到后台继续计时，仅在前台刷新显示。资料按聊天与范围重置导航栈，数据库工作区继续按聊天保留。

「设置 → 壁纸」显示默认渐变和 Phone 上传的图片，使用三列 9:16 缩略图。右上角「+」上传 PNG、JPEG 或 WebP（最大 10 MB），上传后进入全幅预览；选择 Blur 后点「设定」保存并返回图库。上传图片通过 ST 原生图片接口保存到 `data/<账号>/user/images/ste-phone-wallpapers/`，配置只保存所选路径与 Blur，图片内容留在账号目录，不改变 ST 背景。全局设置通过 `extensionSettings.ste_phone` 交给宿主延迟保存。

设置 schema 为 v8，包含手机外形、系统风格、壁纸、模型连接、地图专用模型选择、微信发送模式、AI 历史消息条数、主屏与 Dock 排列，排列中的应用即已安装应用。v7 升级时地图模型初始未选，保留全局默认。v6 及更早版本补默认经典 iPhone 6s 外观，机身和系统风格各自保存。v5 及更早配置升级后将 AI 历史消息条数设为 100，保留已有有效设置。v4 配置升级时保留原配置并将微信发送模式设为延迟发送；v3 配置升级时保留壁纸和连接，并添加默认布局与 App Store。首次读取 v1 时移除旧 URL 列表与旧背景选择，恢复默认渐变并保留 Blur；v2 保留壁纸与 Blur，补上空连接列表和未选择的默认连接。独立预览使用自己的 IndexedDB 保存 Blob、localStorage 保存配置，刷新时重新生成图片 URL；不连接真实 ST。`/?settings=1` 可快捷进入设置，同一局域网 HTTP 预览也支持上传。

「设置 → 模型连接」支持添加、编辑和删除命名连接，配置 OpenAI Chat Completions 兼容服务的 Base URL、API Key、模型 ID 与自定义请求头。Base URL 需要包含服务要求的路径前缀（如 `/v1`），不要填写完整 `/chat/completions` 地址。首个连接保存后自动设为默认，点击连接行选择默认，左侧勾选标记表示当前选择，右侧圆圈 i 进入编辑；也可选择「无默认」，删除默认连接后清空选择。保存显式提交草稿，返回时可确认舍弃；Home 与关闭手机保留草稿，Expose 退出设置或刷新结束草稿。

测试进度、模型回复和失败信息显示在手机内的 iOS 风格弹窗。运行中可取消，失败后可重试；「好」或 Escape 关闭弹窗，关闭运行中的弹窗会取消测试。Home 与关闭手机保留运行及弹窗状态，返回设置后继续查看。

模型请求在浏览器开发者工具 Console 中记录 `[STE Phone AI]` 日志，以 `requestId` 串联请求、HTTP 响应、完成或失败，并标注「日记生成」「微信回复」或「连接测试」。请求日志的 `input` 保存交给 ST 代理的完整协议载荷，包含系统提示词、消息历史、工具定义和生成参数，鉴权字段在发送时单独加入。结束日志集中保存同一份 `input` 与 Pi assistant 消息 `output`，可一起复制排查；输出包含正文、模型返回的思考、工具调用与结束原因，截断、流中断、超时和取消也保留已收到的部分内容。`complete` 表示本次模型传输结束，应用后续的回复解析和保存仍可能失败。错误保留完整 HTTP 响应体、上游 SSE 错误、原始异常与原因链，不截断、不做密钥脱敏；同时写入 Pi 原生 diagnostics，应用包装错误时继续保留这些诊断。失败提示给出对应请求编号。

「日志」应用在手机内展示 Phone 自己的运行日志，当前包括启动信息和上述 AI 请求事件。每条日志记录时间、级别、来源应用、消息和完整详情，可筛选级别与应用、查看结构化文本并复制。日志按条增量写入浏览器 IndexedDB，刷新时读取摘要，打开详情时读取完整正文。最多保留 1000 条、合计 32 MiB（按 UTF-8 计算），达到任一上限时优先清理最旧的记录，同一 AI 请求已保存的事件一起清理。旧 LocalStorage 日志（`ste-phone-logs-v1`）迁移事务成功后才移除旧键。保存失败会在日志应用提示，待写详情在有限内存中仍可查看、复制或重试；超出持久化或待写容量的记录会标明未保存或详情不可用。日志不做脱敏，也不按 ST 聊天区分，卸载应用不会清除已保存记录。独立预览可用 `/?logs=1` 直接进入。

共享传输支持工具定义、工具调用增量、工具结果回传和 Pi Agent 的多轮工具循环；模型思考转换为独立 thinking 内容块。工具注册、思考展示及业务结果要求由应用决定。日记和连接测试目前不注册工具，收到意外工具调用由各应用终止，不触发后续模型请求；两者只提取最终文本，思考不展示、不保存为正文。只有思考而无正文由应用报空回复，输出截断保持各应用原有处理。

连接测试使用当前填写的配置，通过 Pi Agent 和 ST 同源 Custom 代理发送一次简短文本生成，支持流式、取消和 60 秒超时，可能产生少量用量；保存配置不会自动测试。首期仅验证文本生成，未接入业务生成或工具调用。API Key 可以留空，自定义 `Authorization` 优先于 API Key；无鉴权时显式使用空值，避免继承 ST Custom 连接的密钥。请求头名不区分大小写且不能重复，值可为空但不能含换行；`Content-Type` 固定 JSON，传输层请求头不可自定义。API Key 和请求头值明文保存在 Phone 的 ST 设置中，界面默认隐藏，不改变 ST 主连接或密钥。

独立预览的模型测试始终模拟，不联系配置的服务，回复中明确标记模拟结果；`model-test=slow`、`error`、`length` 可分别验收取消、失败与输出上限状态，例如 `/?settings=1&model-test=slow`。Pi 两包锁定 `0.83.0`。生产与预览共用设置模块的 Agent、提示词、输出限制与超时流程，预览仅替换为模拟 AI 传输；生产协议转换位于宿主适配器。

## 开发命令

主屏「资料」可以查看 STE Memory 的当前背景资料、搜索和复制正文。需要同时安装支持 `STE_MEMORY_API v1` 和 `database v1` capability 的 Memory 构建，展示映射支持「剧情记忆」预设；结构不符会明确提示。主屏「数据库」（Fake DBeaver）提供对象搜索、列与关联说明、只读 SQL 和结果复制，提供 `src_*` 源别名及 `phone_*` 标准视图。标准世界时间用 `SELECT date(world_time) FROM phone_world_state;` 查询。公共缓存跨 App 保留，刷新 ST 后重建视图连接，不写回 Memory；SQL 草稿、结果、搜索和滚动位置按聊天及资料范围保留在内存。独立预览使用示例数据，可用 `/?data-source=1` 或 `/?database=1` 快捷进入，加入 `data-state=empty`、`error`、`unavailable`、`unsupported` 检查状态。接口、映射和缓存说明见 [公共数据源](docs/data-source.md)。

「资料 → 人物 → 人物详情 → 编辑」可覆写姓名、性格、背景和现状，也可从图库设置通用头像。覆写按 ST 聊天、稳定资料空间和人物保存。「恢复来源」在保存时移除该字段的覆写，采用 Memory 的当前值。微信、日记和 Twitter 的人物读取采用有效资料，Twitter 账号自定义头像优先。Fake DBeaver 和剧情地图继续查询来源。独立预览可附加 `character-override-test=save-error` 或 `slow-save`，分别检查保存失败重试和保存状态。

```sh
pnpm build             # JS、CSS、manifest；清理旧 Worker/WASM
pnpm watch             # 增量构建；配置 .env 后自动同步到 ST
pnpm preview:frontend  # 独立预览，共用生产组件与 CSS
pnpm typecheck
pnpm lint
pnpm format:check
pnpm test              # 串行验证工程接入、资料缓存、远端查询与标准视图 SQL
```

生产入口为 `src/frontend/index.ts`，与独立预览共用 `src/bootstrap/create-phone.tsx` 组装设置、资料、数据库工作区与应用页面，入口分别注入宿主或模拟适配器。`src/apps/<应用>/` 集中各应用业务与 `ui/` 页面；`src/frontend/host/mount-phone.tsx` 挂载 React 与 Shadow DOM，`phone-app.tsx` 管理窗口开关。`frontend/device/` 放机身与会话，`frontend/system/` 放状态栏与转场，`frontend/foundation/` 放基础视觉组件，`frontend/apps/home/` 放主屏，`NavigationStack` 提供保留 DOM 的页内导航，`frontend/theme.css` 汇总 CSS 与主题变量。React 随插件打包。手机外壳使用 Inter 并优先使用 Apple 平台字体；日记界面使用 Noto Serif SC 衬线体，正文使用 LXGW WenKai 手写体。字体由挂载入口通过 Google Fonts 与 jsDelivr 声明，不进入产物；网络不可用时回退到 Georgia、楷体或本机衬线字体。构建产物的 manifest 版本与运行时版本统一读取 `package.json`。

全局设置与存储约定位于 `src/apps/settings/`，`public.ts` 提供壁纸读取、模型连接摘要与显式连接配置副本。公共资料、查询结构与来源缓存归 `src/apps/data-source/`，通过 `DataAppPublic` 供其他应用读取；`src/apps/database/` 只持有 SQL 草稿、结果、搜索与滚动等编辑工作区。Memory 数据库连接、协议和视图定义位于 `src/infrastructure/ste-memory/`，ST 设置、图片、AI 传输与聊天通知适配位于 `src/infrastructure/host/`；`src/core/ai/` 和 `src/core/chat/` 声明传输及当前聊天契约。各应用公开读取不依赖页面打开，跨应用仅通过所属模块的 `public.ts` 调用。职责与依赖见 [模块架构](docs/architecture.md)，资料接口与缓存见 [公共数据源](docs/data-source.md)。

## ST 安装与开发直连

将 `.env.example` 复制为 `.env`，配置 `STE_ST_INSTALL` 或 `STE_ST_EXTENSION_DIR`，两者选一。相对路径以本仓库为基准。`.env` 不进入 Git。

推荐通过 Junction 让 ST 直接读取 `dist/`：

```sh
pnpm build
pnpm st:link
pnpm watch
```

`STE_ST_INSTALL` 自动推导目标目录 `public/scripts/extensions/third-party/ste-phone`。Windows 创建 Junction，其他平台创建目录符号链接。链接指向当前工作区的构建产物；修改后需刷新 ST 页面，入口为右下角“手机”按钮。

```sh
pnpm st:unlink         # 仅解除当前 dist 对应的链接，保留 dist 内容
```

目标若已存在真实目录、指向其他位置的链接或断链，命令报错并保留原内容。Worktree 开发前核对链接指向，避免构建目录与 ST 加载目录不一致。

也可以使用拷贝部署：

```sh
pnpm deploy:st         # 生产构建，再拷贝三个发布文件并清理旧 Worker/WASM
pnpm sync              # 单独同步已有构建产物
```

`watch` 没有配置目标时仅构建；配置后在构建成功时同步。目标已直连当前 `dist` 时跳过拷贝。修改 `package.json` 后重启 watch。

## 发版

发布分支为 `release/sillytavern-plugin`，分支根目录仅放插件产物和安装说明。源码在正常开发分支维护，发版命令不会切换当前工作区的分支。

先更新 `package.json` 与源码 `manifest.json` 的版本，执行检查并提交源码，然后运行：

```sh
pnpm release:st --dry-run # 构建验证，允许源码未提交，不修改发布分支
pnpm release:st           # 离线生成或更新本地发布分支并提交

```

发版 worktree 固定在主仓库 `.worktrees/release/sillytavern-plugin/`。命令拒绝未提交的源码、未提交的发布内容，以及发布分支中的非产物文件；推送使用普通 Git push，不强制覆盖远端历史。重复运行相同版本和源提交不会新增提交。

公开仓库为 [Etsuya233/ste-phone](https://github.com/Etsuya233/ste-phone)，ST 安装分支为 `release/sillytavern-plugin`。发布分支 README 同步注明最低 Memory 版本，后续通过扩展面板的 Update 更新。

## 微信朋友圈

从「微信 → 发现 → 朋友圈」阅读动态，点击「发布」以当前帐号分享文字及合计最多 9 个图片、视频媒体，支持混排。发布页以三列网格管理图片，点按图片进入单图页编辑描述与 Prompt，正文与媒体均为空或任一媒体描述为空时「发布」保持禁用。发布前可以从图库选图、让 AI 完善 Prompt 并逐张手动生成，也可先发布描述、之后在详情补图；允许仅媒体，图片与视频共享 9 个名额，可分别添加、排序和删除，删光媒体后可直接发布正文。每张图片独立保存简短描述、可编辑的绘图 Prompt 和可选图片引用，调序与删除一起移动这些信息。旧图片描述保留为占位，直到用户选择或生成实图。微信数据 v2 使用有序媒体数组；读取 v1 时通过迁移链统一转换旧媒体结构，下次正常保存时持久化。打开页面不主动写回，v2 中的旧媒体对象或未来版本明确报错。点击动态阅读全部内容和评论，可发表评论或回复某条评论；评论平铺显示。切帐号后共享同一范围的历史，各帐号只能删除自己的动态和评论；删除原评论后，其他人的回复保留并注明原评论已删除。

详情中的每张图片均可编辑 Prompt、让 AI 完善 Prompt、从图库选择或手动生成。AI 发布动态时同时生成简短描述与详细绘图 Prompt，明确人物姓名、已知外观与衣着、动作、环境、光线及构图；已有描述可结合动态正文和人物资料完善，用户确认后才调用 Image Hub。人物名字用于参考图自动匹配，参考图开关和生图配置沿用 Hub。每次只生成当前一张，不自动生成整条九宫格；后端返回多张时关联首张，其余留在图库。实图保存到 Hub，朋友圈只保存引用，不删除图库文件；失败保留原动态和描述。当前资料范围内也可为其他人物发布的动态配图，不改变作者、正文和评论。互动模型继续读取图片描述，不发送图片文件地址或图片内容。

「AI 生成动态」先选择发布人物，完整生成后进入同一个草稿编辑页，保留作者；可修改正文与媒体、逐张手动生图，点击「发布」才保存动态；「AI 生成互动」为当前动态生成 0—5 条评论，可让人物互相回复，排除当前操作帐号。两者复用 Phone 默认模型连接，手动发布、评论、阅读和刷新不调用模型。AI 取材使用人物资料、各自回复指导、剧情总结、世界状态与最近清洗后的 10 条 ST 消息；发布另取单人关联背景及该人物最近 10 条动态，互动取目标动态及最近 50 条评论和直接回复目标。不读取微信私聊，也不回写 ST 正文或 Memory。

朋友圈按 ST 聊天与稳定资料空间保存，切换帐号只改变操作身份。人物离开或资料不可用时，已保存内容仍可只读查看。Home 和关闭手机保留未发布草稿并继续生成；离开草稿需确认舍弃，已生成的图片仍留在 Hub 图库；切帐号、切聊天、切资料实例或从 Expose 退出微信可取消生成。互动和已发布动态配图进入保存后继续提交到原聊天，保存期间隐藏停止按钮。微信同时最多一项 AI 任务，生成失败或输出不合法不保存半批；AI 保存失败直接报错，可显式重新生成，手动保存失败保留草稿。不增加跨标签同步、冲突合并或后台恢复。

独立预览使用 `/?wechat=1&moments-test=demo` 展示媒体、评论和历史人物样例；`moments-test=empty/slow/error/invalid/length/save-error` 分别模拟空互动、慢生成、请求错误、非法 JSON、截断和保存失败。`moments-test=slow-save` 可检查保存期间的界面。预览复用生产取材与协议，仅返回模拟内容，不请求真实模型；默认模型连接仍需在预览设置中配置。

### 互动参与人物

点击「AI 生成互动」后，可勾选最多 5 位人物，再点「生成互动」。每位选中人物至少回复一条，整批最多 5 条，未选人物不会发言；不勾选或点击「清空选择」时，由 AI 自行挑选，也可能无人回应。当前微信帐号不参与 AI 代写。模型遗漏选中人物时整批报错，不保存部分评论；页面保留选择供重试。选择仅用于本次操作，Home 和关闭手机保留，重新进入选择页恢复默认自动模式。

动态作者选择页和互动参与人物页支持可选「本次用户指引」，用于调整主题、语气、配图方向或互动重点。动态页先填指引，再点击人物起草；互动页填写并选择人物后点击「生成互动」。提交时固定本次输入，生成期间暂不可编辑，失败后保留输入和选择供调整重试；Home 和关闭手机保留，重新进入生成页清空。留空沿用原行为，指引不保存到人物长期指导或动态数据，不改变人物资料、知情范围、参与名单与输出格式。动态仍进入草稿待发布，互动继续整批保存。

## 剧情地图

正式地图使用 OpenLayers Canvas 绘制，库负责平移、缩放、点击命中与标签碰撞避让。应用维护语义样式、标签优先级、查询高亮和提案旧轮廓；平移与缩放复用地图实例，文档变更才更新要素源。Home 和关闭手机保留视角，Expose 退出释放实例。接入与验收记录见 [OpenLayers 验收报告](docs/performance/2026-11-06-openlayers-integration.html)。

「地图」用平面示意图展示地点、区域、道路和事件。可以描述首张地图、搜索并选择已有地点，或点击地图空白处指定位置后发指令。底部地图助手可向上拖动或点「全屏」铺满手机屏幕，对话、思考和工具调用在可滚动区域内显示，输入区固定在底部；收起后只保留标题栏。助手对话按 ST 聊天和稳定资料空间保存在当前浏览器，重开后恢复。后续请求按原顺序追加消息，保留原有请求前缀供模型供应商缓存。「新对话」取消进行中的任务并清空对话、待确认提案、选中地点或坐标和输入草稿，不删除已保存地图与撤销记录。修改先生成金色高亮的提案，确认「应用修改」后保存，也可继续调整或放弃。局部修改保留无关几何，应用后可撤销一次，撤销结果同样保存。查询和路线仅临时高亮已有要素，路线沿已有且连通的道路显示。

助手默认可以读取全部 Memory 公开业务表与剧情总结，按需查看资料目录，再分页读取相关记录；不再要求选择资料范围或单独点击「从剧情更新」。地点通过稳定记录身份关联，显示来源与补充依据，位置不明的地点保留「位置待定」，事件未知时刻显示「时间未知」。地图按 ST 聊天与稳定资料空间隔离，不回写 Memory 或 ST 正文；模型或 Memory 离线时仍可浏览保存的地图。生成前在地图助手的「模型连接」中，从设置已配置的连接中明确选择。地图跨聊天和刷新记住所选连接。所选连接删除后提示重选，生成与保存期间暂停切换。每次生成在开始取材前固定本次连接配置。Home 和关闭手机继续生成，Expose 退出及切聊天取消；已提交的原聊天保存等待完成，保存失败保留提案可重试。

独立预览 `/?map=1` 展示固定示例，`map-test=empty/slow/error/invalid/length/save-error` 检查空图、慢生成、失败、非法 JSON、截断和保存失败。预览使用模拟连接，不请求真实模型，地图独立保存到 localStorage。新配置默认安装，旧桌面可从 App Store 获取。

地图几何允许粗略示意。当前校验坐标、稳定身份、要素和事件引用、区域归属及查询路线连通；多边形自交、道路穿越水域和真实比例尺尚不自动检查，用户须在提案预览中确认。事件关联不提供完整历史地图回放。

地图丰富化使用可选制图信息表达自然地形、街区、重要建筑轮廓与主次道路。街区内的不具名楼块和绿化由独立种子生成，作为背景示意，不进入剧情地点列表、事件或模型上下文；沿用旧地图数据时无需迁移。楼块遵循所在多边形，避开已知水域、道路和地标，修改其他远处街区不会使原街区楼块重新随机排列。详细地图生成默认输出预算为24576 token，较早期增加以容纳轮廓和路网；截断仍整批拒绝，生成不会自动应用。

地图助手采用原生工具循环。它先读取当前草稿，并可按需查阅全部公开剧情资料表、记录页或剧情总结。每次增量修改留在当前任务的私有草稿，检查发现引用或几何问题时，助手可以修正并重新检查。最后一次修改通过检查后才显示提案，由用户点击应用保存。对话按轮展示用户指令与最终说明；每次运行的思考、工具调用和中间旁白按发生顺序收进同一个「过程」组，运行中默认展开，结束后默认收起，只保留最终说明。组内的思考和每次工具调用也可分别折叠，思考内容随模型流式返回逐步更新，展开后最多显示三行并滚动。查询沿用已有地图与道路，返回临时定位或路线。地图助手可手动停止，应用不限制任务总耗时、模型轮次、工具次数、连续失败次数或输出 Token。模型供应商截断时结束本次任务，已发送的对话与配齐结果的工具调用继续作为后续上下文。日志记录任务指令、工具调用与结果及最终状态。
