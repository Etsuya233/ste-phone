# 备忘录 App 需求与实现思路

2026-11-12。STE Phone 内置应用首版已实现。需求由主代理与 GPT‑6.1 Sol 逐轮讨论，并按用户反馈修订。界面由 OpenCode 的 CommandCode DeepSeek V4.1 Flash 优化。

## 产品目标

在小手机中为角色记下想法、整理文字和图片，也可以让 AI 起草，再由用户编辑保存。例如，选中角色后写下「周末计划」，在两段之间插入地图截图，再让 AI 补一段行李建议。下次打开备忘录，直接回到上次选择的角色列表。

体验参考 iOS 备忘录的列表、首行标题和连续图文编辑。首版提供新建、编辑、保存、搜索和删除，以及 AI 起草与插入文字。文件夹、置顶、清单、协作、回收站、直接上传及 App 内生图留待后续讨论。可先在图库上传照片，或在图乐园生图，再从备忘录选入。 [Apple 备忘录编辑说明](https://support.apple.com/en-eg/guide/iphone/iph1ac0b3a2/ios)

## 列表与编辑

每条备忘录属于一个角色。首次进入时选择角色，此后记住上一次选择，刷新后也会恢复。列表顶部可以切换角色，只显示和搜索所选角色的备忘录。手动新建和 AI 新建都归当前选中的角色。角色列表提供当前 Memory 人物、已保存笔记的角色和上次所选角色。已有笔记在人物资料暂时不可用时仍可查看和编辑。切换 ST 聊天不自动切换所选角色。

- **列表**按修改时间倒序显示标题、摘要和时间，支持按文字搜索。标题取正文首个非空文字行，摘要从其后的文字派生。仅含图片时显示「图片备忘录」。删除已保存条目需确认，保存成功后从列表移除。
- **编辑**在同一个正文区输入和粘贴纯文本、换行、选字和撤销。点击「插入图片」后从手机图库或 Image Hub 选择，确认后在原光标处插入独立图片块，保留光标两侧文字与顺序。若选中了文字，插入点取选区末尾。图片前后均可继续输入；支持点开查看、从正文移除。可多次插入同一图片，移除某处只解除该处引用。原图不可读时，正文原位置显示可移除的占位。
- **保存**点击「完成」或从编辑页返回列表时提交有变化的草稿，宿主确认后更新列表并返回。新建空白草稿退出时不产生条目；已有条目被清空时提示补充内容或使用删除操作。仅含图片可保存。保存失败留在编辑页，原草稿完整保留供重试；用户也可以确认舍弃本次编辑后返回。保存期间暂停重复提交和编辑。

## AI 写作

列表提供「AI 新建」，编辑页提供「AI 写作」。两者都填写本次指令，沿用 Phone 默认模型连接，先预览完整的纯文本候选。点击「使用文字」才创建一份可编辑的新草稿，或将候选插入当前草稿；随后仍需通过编辑页保存。停止、放弃、空输出、截断或失败均不修改正文，失败后可沿用指令重试。无默认模型连接时可提示前往设置，手动编辑仍可用。

模型收到本次指令与固定写作要求。当前备忘录正文、选区、图片、其他备忘录和 ST 剧情均不自动进入请求。首版已有备忘录只支持插入文字，润色选区、整篇改写和剧情取材留待后续。

从提交生成到采用或放弃候选，原草稿保持只读，暂停手动编辑、插图和切换角色。生成期间可查看预览或停止，生成结束后可采用或放弃。已有草稿发起时固定插入点，有选区时取末尾。采用后在该位置一次性插入候选文字并恢复编辑，可撤销这次插入。停止、失败或放弃后恢复原草稿的编辑。每个 App 会话同时处理一项生成。

## 离开与恢复

Home、切换手机内应用或关闭手机保留草稿和任务。生成始终归发起时所选的备忘录角色。离开编辑页或「AI 新建」时，若还有任务或未采用的候选，先确认放弃；确认后停止任务并丢弃候选，再按原流程返回。打开图库选图仍属于当前编辑页。

从 Expose 退出或卸载 App 时，未保存草稿需先在原页面保存或确认舍弃；仍在生成或预览候选时也需确认放弃，适用于尚未创建草稿的「AI 新建」。保存已提交时等待结果。刷新 ST 后恢复已保存条目，内存草稿及未采用候选随原会话结束。重新安装可读取已保存的备忘录。

## 实现思路

1. **应用接入。** 在 `src/apps/notes/` 维护备忘录记录、编辑会话、AI 任务与存储契约。沿用 [App 目录](../../src/core/launcher/catalog.ts) 和 [组装入口](../../src/bootstrap/create-phone.tsx)，新桌面默认提供入口，现有桌面从 App Store 获取。列表、编辑和图库选择各自维护页面交互，复用 Foundation 导航、搜索与弹层。独立预览使用 `/?notes=1`，注入模拟模型和独立存储。
2. **文档编辑。** 每条记录保存 ID、角色引用、创建时间、修改时间和有序正文。正文由文字段落和图片块组成，标题和摘要从正文派生。ProseMirror 管理连续编辑、选区和撤销，图片块复用图库引用。Phone 在 Shadow DOM 内按光标所在行避让软键盘。 [图库公开接口](../../src/apps/gallery/public.ts)
3. **角色与保存。** 从资料应用读取 Memory 人物，沿用稳定资料空间和人物身份区分同名角色，保存角色名称供资料暂时不可用时显示。每个 ST 登录账号使用一份带版本的 `user/files/ste-phone-notes.json`，保存条目和上次选择的角色。复用 ST 文件读写方式，每次提交保存整份数据，成功后更新列表。单页串行提交，首版不做跨页面冲突检测和合并。 [资料公开接口](../../src/apps/data-source/public.ts) · [图库宿主适配器](../../src/infrastructure/host/gallery-storage.ts)
4. **AI 接入。** 复用 [默认模型连接读取](../../src/apps/settings/public.ts) 和现有 AI 传输。提交时固定指令、连接、所属角色和插入点。生成和候选预览共用只读状态，采用后恢复编辑。已结束会话的迟到结果直接丢弃。

实施顺序为图文编辑与保存 → 列表和现有图库 → AI 写作。先跑通「手写、插图、保存、刷新后重开」，再接候选插入，便于单独验证存储和编辑器。

## 验收

| 场景 | 预期 |
| --- | --- |
| 输入两段文字，中间插图，再输入第三段；保存后刷新 | 图文顺序一致，图片可打开和移除，图库原图保留。仅图备忘录可保存，空白新建不留条目。 |
| 为两个角色分别新建笔记，切角色后搜索，再刷新 ST | 每个角色只看到自己的条目，恢复上次所选角色。已有笔记无需模型或实时人物资料即可编辑。 |
| AI 新建后放弃候选；接受另一条后改字、插图、保存 | 放弃不留条目，接受先进入草稿，最终只保存用户确认的编辑结果。 |
| 在正文中发起 AI 写作，尝试打字、插图和切角色 | 生成和预览期间只能查看，采用后从原插入点加入文字。停止或失败后可继续编辑原草稿。 |
| 首次保存失败后重试 | 失败时留在编辑页并保留草稿，保存成功后列表显示该条目。 |
| 在 320px、390px 和移动端真机编辑，再从 Expose 退出 | 中文输入法、粘贴、软键盘下的光标和工具栏可用；Home 保留草稿，明确退出按未保存规则处理。宿主文件写入和账号隔离在真实 ST 验收。 |

## 关键问答与修订

| 讨论问题 | 当前方案 |
| --- | --- |
| 切聊天或角色后，是否还是同一份列表？ | 经用户确认，按角色查看和新建笔记，切聊天时保留角色，重开恢复上次所选角色。 |
| AI 从哪取材，结果何时写入？ | 只传用户本次指令。模型生成候选文字，经用户采用后进入草稿。 |
| 图文怎样混排，生成时如何操作？ | 沿用 Sol 建议的连续编辑区。经用户确认，生成和预览期间暂停编辑，采用后插在原位置。 |
| 是否在备忘录里直接生图？ | Sol 提议复用 Image Hub 做独立入口；首版保留从图库选图，生图沿用图乐园。 |
| 保存需要处理多页面同时写入吗？ | 经用户确认，首版保留单页保存和失败重试。 |
