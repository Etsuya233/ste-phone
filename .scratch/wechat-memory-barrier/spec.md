# 微信记忆屏障与历史消息条数配置需求

状态：GPT-6.1 Sol 已在主代理指导下实现，主代理完成代码审查、独立预览及 ST 接口验收。2026-11-03。

用户已确认修订后的方案并授权开发。本文保留需求与验收口径；除用户明确提出的方向及默认100条配置，其他细节来自此前两位代理的质询推演。[实现思路](implementation.md)与[问答记录](discussion.md)随文保存。

## 目标与方向

用户已明确方向：微信聊天支持名为“记忆屏障”的功能，可任意插入、临时关闭及重新开启；AI 只能读取屏障之后更新的微信消息。此修订取代最初讨论中的反向解释。

按消息从旧到新的顺序：`A → B → 屏障 → C → D`，屏障开启时，允许读取 C、D，A、B 被排除。每轮应用用户配置的最近 N 条消息窗口，默认100条；屏障之后本轮待回复的消息完整保留。后续新消息和回复自然累积在屏障之后，能够延续这些较新的往来。

界面须明确提示：“AI 仅使用屏障之后的微信消息。”待回复队列也遵守边界，屏障前的旧队列不能绕过限制。关闭屏障恢复旧消息的历史读取资格。

## 作用范围

屏障属于当前 ST 聊天中的一个双人微信单聊，双方帐号视角共用屏障与开关。其他单聊、其他 ST 聊天独立。屏障和开关跨刷新保存，关闭手机、Home 与切帐号均保留。

屏障只筛选当前单聊的微信消息。人物资料、剧情总结、关联背景、世界状态、最近 10 条 ST 消息和可用表情继续按原规则提供；这些来源可能包含与被排除微信历史相同的事实。界面管理说明须写明“仅限制微信历史，剧情背景与 ST 消息仍会提供”。

屏障不删除、修改或隐藏用户阅读的聊天，不回写 ST 正文或 Memory，不保证模型忘掉其他来源中的同一事实。每次生成仍采用独立固定输入。

## 插入与管理

支持在首条消息前、任意两条消息之间、当前最后一条消息后插入。空会话支持插入唯一的起始屏障，此时创建只有屏障的单聊记录，保留已有双方身份。

屏障固定在选定边界。末尾插入后发送新消息，新消息位于这道屏障之后；屏障不会追随末尾移动。文本和表情消息都可作为边界，允许插在同一 AI 回复批次的两条消息之间。

每道屏障插入后默认开启，支持独立关闭、重新开启和删除。删除只移除屏障记录；消息和草稿保持原样，不自动触发队列回复。相同位置只保留一道屏障，再次插入时定位已有屏障并保留其开关，避免无意重新开启。

首期通过删除再插入改变位置，不增加拖拽或专用移动模式。不增加全局总开关、屏障名称、自动屏障或时间驱动屏障。

聊天顶栏加入操作菜单，保留资料入口，提供“在最前插入记忆屏障”“在末尾插入记忆屏障”。每条消息的可访问操作菜单提供“在此消息前插入”“在此消息后插入”，鼠标、触控与键盘均可操作；长按可作为额外快捷方式。首条前等价于起始位置，其他消息前等价于上一条消息后。

消息流中以独立分隔条显示“记忆屏障”，包含可直接操作的开关与删除菜单。分隔条区分“已关闭”“生效中”“已开启，受更新屏障限制”，不能仅靠颜色表达。聊天菜单展示当前生效边界与上述范围说明，便于屏障滚出屏幕后确认限制。

插入、开关及删除保持当前阅读位置；在可见位置操作时让该屏障可见，在最前/末尾插入时滚动到目标。操作完成后恢复合理焦点，不触发新消息提示、时间分隔或会话排序变化。

## 多屏障规则

开启的屏障同时构成限制，按消息顺序最新的一道生效。更早的屏障保留开启状态，关闭更新屏障后可直接接替，无需重新开启。

| 消息排列                  | 开关状态     | 允许的消息范围           |
| ------------------------- | ------------ | ------------------------ |
| A · 屏障1 · B · 屏障2 · C | 两道均开启   | C                        |
| 同上                      | 1关闭、2开启 | C                        |
| 同上                      | 1开启、2关闭 | B、C                     |
| 同上                      | 两道均关闭   | A、B、C                  |
| 屏障 · A · B              | 开启         | A、B                     |
| A · B · 屏障              | 开启         | 空历史；新消息追加后可读 |

上表范围均须继续经过消息窗口裁剪。屏障数量与最近 N 条消息计数无关，生效状态由已有消息顺序与开关推导，不另行保存。

## 微信设置与历史消息条数

与记忆屏障同批实施。在“微信 → 我 → 设置”中增加“AI历史消息条数”，默认100。使用可编辑的数字输入与显式保存，允许填写正整数；不提供0、负数、小数或“无限制”。不得静默截断、取整或把非法输入改成100；空值、非法值与超出安全整数范围须显示错误，保留原已保存配置。

这项配置作为微信全局偏好，跨微信帐号、单聊和ST聊天共用，生产按ST登录帐号保存，独立预览使用自己的存储。已有用户升级后从原固定30条改为默认100条，保留其他设置；新用户默认也是100条。这是本次产品行为调整。

数字按双方实际消息条目计数，每条文本或表情各计1条；同一AI回复拆出的多条消息分别计数，时间分隔和记忆屏障不计数。它约束模型输入，不限制聊天展示、保存数量、其他背景材料或最近10条ST消息。

先按最新开启的记忆屏障截取更新消息，再从获准序列中取最近N条。屏障后消息不足N条时全部提供，不从屏障前补齐；关闭全部屏障时从完整单聊取最近N条。屏障后本轮待回复P完整保留，因此当前批次跨度超过N时，实际提供条数可以超过N。N包含窗口内的双方消息与P，不采用“N条历史再额外追加P”的常规扩窗方式。

例如N=100、屏障后已有150条且本轮输入位于末尾时，通常提供最后100条；屏障后仅40条时提供40条；屏障后有120条连续待回复消息时完整提供120条。

每次请求在开始读取异步背景资料之前固定N；保存新值仅影响下一次生成和手动重试，已经运行的请求继续使用原值，不自动停止或重新生成。设置保存不触发AI、不消费队列、不改变屏障。

设置页编辑期间的值是草稿，保存成功后回显新值；保存失败显示错误、保留输入草稿与原已保存值。返回时存在未保存修改需确认舍弃，Home和关闭手机保留草稿，退出微信或刷新结束未保存草稿。发送模式保持原入口，首期只增加这项历史窗口配置。

## 本轮输入与窗口

每轮开始时依据完整单聊及当前发言人物，沿用现有规则固定原待回复集合 Q，再与生效屏障之后的消息取交集，得到实际本轮输入 P。P包含获准的延迟队列、当前提交的文字或表情、停止或失败后仍待回复的消息；Q中屏障之前的旧消息不传给AI。没有开启屏障时P等于Q。

允许消息序列只包含生效屏障之后的消息，不为待回复消息添加越界例外。在此序列上应用最近 N 条且完整覆盖 P 的窗口规则，再将窗口拆成“历史”和“本轮输入”，同一消息只提供一次。本轮任务由 P 是否为空决定。

回复整批保存成功后，原待回复批次 Q 整体结束：P获得回复，屏障前的部分视为用户通过屏障跳过，原消息仍保留，不将其标记为AI已经阅读或回答。关闭屏障可恢复这些消息的历史资格，已经跳过的旧队列不会自动重发。失败、停止与重试保持原Q；下一次调用按当时屏障重新计算P。界面说明：“屏障前的待回复消息将跳过，成功生成后结束原队列。”这条队列处理是代理随方向修订补充的约定。

空输入、有 P 时回复 P；无 P 时主动开口。末尾屏障使既有消息全部不可读时，允许仅结合背景开口，生成的回复位于屏障之后。插入、开关和删除本身不消费队列，也不触发AI。

所有传给模型的历史时间、首条待回复时间、此前消息时间、最后消息时间与间隔，只能从允许消息序列和当前设备时间计算。首条获准消息的上一条若位于屏障之前，间隔必须为空；不得使用旧消息时刻补算。窗口外但仍位于屏障后的上一条消息可用于计算间隔。

屏障记录自身不进入提示词消息数组，不冒充用户或 AI 发言，也不生成虚构发送时间。实际发出的提示词日志沿用现有记录规则；屏障不会追溯清理此前日志。

## 保存、生成与失败

发送保存、生成、回复保存、停止撤回、屏障保存期间，整个微信服务禁止屏障增删开关。生成中保留既有停止按钮；停止完成后用户可修改屏障，保存或撤回期间等待结束。禁用操作旁说明：“回复或保存结束后可修改；生成中可先停止。”

屏障变更须先保存成功，再更新生效状态；保存期间显示进行状态。失败保留原位置与开关，显示错误，允许用户再次操作，不自动重试。屏障保存不清草稿，不消费待回复消息，也不触发 AI。

屏障保存持有现有服务的全局写入互斥，期间发送、队列、帐号切换及其他屏障修改均禁用。保持每次生成的消息、屏障与待回复输入不变，避免旧回复快照覆盖新的屏障。

切 ST 聊天仍允许。已经发起的屏障保存固定原目标，全局锁保持到原操作结束；迟到结果不得发布到其他聊天或已重新加载的同 ID 聊天。原操作失败通过标注原目标的操作错误反馈，不污染新聊天的回复错误。返回原聊天时以持久化结果重新读取屏障。

## 数据与兼容

历史消息条数归全局手机设置，计划将设置schema从v5升级至v6，新增 `wechatHistoryMessageLimit`，默认100；v5及更早版本按现有迁移规则保留有效设置并补100。字段存在但非法时明确报错，禁止借兼容迁移掩盖损坏数据。微信聊天数据仍沿用v1，与全局设置版本分别演进。

在现有微信 v1 会话中添加可选 `memoryBarriers` 字段，每条记录拥有唯一 ID、消息边界与 `enabled`。旧会话字段缺失明确表示没有屏障，首次修改写入此字段；另加可选的按人物保存的队列处理截止位置，用于记录已回复及明确跳过的批次；缺省沿用旧数据规则。不升级微信根版本，不改写旧消息。

边界使用消息 ID；首条前使用空边界，禁止按时间戳、数组索引或消息文本定位。消息顺序以数组原序为准。屏障不影响会话摘要、最后消息时间、列表排序或待回复计数；只有屏障的空会话暂不进入“微信”会话列表，从通讯录重新进入仍可管理，出现第一条消息后按消息时间进入列表。

无效锚点、重复屏障 ID、重复位置或非法字段明确报错。保留原始消息供阅读，该单聊暂停生成与屏障编辑，禁止静默忽略屏障或扩大读取范围。其他正常单聊保持可用。首期不提供损坏数据修复入口。

ST 分支如果复制当前聊天元数据，屏障随之继承；不增加独立的分支恢复、历史楼层回退或导出协议。旧版插件不会执行新屏障限制，降级后的行为不在本功能保证范围内。

## 验收条件

| 场景                                         | 必须观察到的结果                                              |
| -------------------------------------------- | ------------------------------------------------------------- |
| A、B、屏障、已完成C/D、新输入E               | 模型只得到获准窗口内的C/D和E；下轮E及其回复继续具备读取资格   |
| 待回复A、对方B、屏障、待回复C、对方D         | 只提供C和获准窗口内的D；A/B不出现，成功后A作为旧队列跳过      |
| 延迟队列超过N条，队列跨屏障                  | 仅屏障后P完整且去重，旧队列不越界；成功结束原批次，失败保留   |
| 屏障后历史超过N条                            | 先过滤再裁剪，可读取屏障后最近窗口；无屏障时按配置N取最近窗口 |
| 两道屏障逐个关闭、开启或删除                 | 按上表切换，其他屏障开关保持                                  |
| 首条前、任意消息间、AI批次中间、末尾、空会话 | 位置准确，新消息追加不移动原屏障，同位置不重复                |
| 隐藏消息拥有独特正文、时刻与长间隔           | 最终模型载荷没有正文、时刻或由隐藏消息计算的间隔              |
| 停止、失败重试、空输入主动开口               | 失败与停止不消费Q，重试重新计算P；全部被阻隔时主动开口        |
| 刷新、双方切帐号、切ST聊天、旧v1数据         | 屏障正确保留或隔离，旧数据默认无屏障                          |
| 保存失败、慢保存期间切走再返回               | 旧状态与目标归属正确，迟到结果不覆盖当前会话                  |
| 生成、保存、撤回过程中尝试修改               | 控件与服务均阻止并发写入，停止完成后恢复操作                  |
| 损坏锚点或重复边界                           | 受影响单聊明确报错，消息可读，不向AI发送该单聊                |
| 桌面、320px与390px界面                       | 操作可达，状态文字明确，焦点、阅读位置和菜单边界正确          |

配置验收还须覆盖新用户默认100、旧配置升级为100、填写30/100/200、非法输入与保存失败、刷新及跨帐号/聊天恢复、修改N不影响运行请求，以及设置页窄屏操作。通过最终载荷核对窗口条数，包含不足N条、超过N条、P超过N条和屏障后不足N条不回填旧消息。

实现验收须检查最终发给模型的载荷，不能只检查界面分隔条。独立预览通过后，使用专用 ST 测试聊天检查持久化、刷新与聊天切换；179项全量测试、类型检查、Lint、格式检查、构建及diff检查通过；桌面和320/390px预览的实际AI载荷、菜单、焦点、刷新及失败恢复通过；独立ST单聊/群聊与设置接口往返通过。真实ST手机UI端到端、真实模型和移动真机未验收。详细入口与保留的行数例外见 [实现记录](implementation.md#实施结果)。
