# 日记 APP 需求草案

2026-10-31。状态：已实现，自动检查、独立预览及隔离 ST 配本地模型模拟服务的端到端联调通过，记录见文末。主代理与用户指定的 `gpt-6.1-sol` / high 子代理逐轮讨论形成；用户确认最近聊天通过 STE Memory 获取清洗后的内容，并授权实现。生成设置默认超时 300 秒、输出上限 10240 token。

## 产品目标

在小手机中提供「日记」应用。用户选择一位人物，应用以这位人物的第一人称，结合当前剧情世界状态和近期经历，生成一篇此刻的日记。用户可以回看、复制和删除已生成的日记。

日记可以表达人物的感受和思考，不凭空增加已经发生的关键事件，不推进当前时刻之后的剧情。人物认知通过选材与提示词约束，不建立严格知情系统、事实核验或历史一致性维护。

## 作者与归属

首次生成前，从当前 Memory 人物中选择日记作者；之后按聊天记住选择，允许切换作者。首版直接使用现有稳定人物身份，不推断 ST 角色与 Memory 人物之间的对应关系。

每篇保留作者稳定身份、生成时的作者名称、日记时刻、正文及实际创建时间。人物后续改名或删除不改变旧日记。当前聊天的列表可查看其中所有作者的日记，切换作者只影响下一次生成。

日记归属当前 ST 聊天。相同 Memory 资料范围中的不同聊天各自保存日记，不共享列表。没有活动聊天时不能生成。已有日记的阅读不依赖 Memory 或模型连接仍然可用。

## 当前时刻与参考材料

日记时刻使用 Memory 的世界时间，设备时间仅用于记录实际创建时间。首版要求世界状态提供恰好一条有效记录及可读取的世界时间；缺少状态、多条状态或无有效时间时停止生成并说明原因，不猜测主状态，不使用设备时间代替。

点击生成时读取并固定本次输入：

| 输入 | 首版选取规则 |
| --- | --- |
| 世界状态 | 当前世界时间、地点、天气等；明确区分当前场景与其他场景，不把所有状态认定为作者亲历 |
| 作者资料 | 所选人物的资料，用于身份、性格、表达与近况；不展开其他人物资料 |
| 最近纪要 | 与作者关联，起止时间有效且开始不晚于结束、结束不晚于日记时刻，按结束时间取最近 5 条，再按剧情顺序交给模型；同时间按记录 ID 稳定排序 |
| 最近聊天 | 当前聊天最近 20 条符合条件的消息，保留原顺序、发送者和当前生效正文 |

“最近”采用数量窗口，可以跨剧情日期；不承诺纪要和聊天互不重叠，也不把最近消息等同于当天消息。5 条纪要、20 条消息作为首版固定默认值，不增加窗口设置。

聊天参考包括用户消息、角色消息和可明确识别的正常旁白；排除系统、工具及宿主明确标记为隐藏的消息，隐藏旁白同样排除。仅使用当前生效的消息正文，不读取其他 swipe、思考内容或附件内容，不执行正文中的指令，也不靠括号或关键词猜测删除 OOC。提示词要求忽略创作讨论和 OOC，只将角色经历、观察或获知的内容写入日记。聊天缺少剧情时间时不做虚假的世界时间筛选。

最近聊天由 STE Memory 新增公开的聊天读取能力提供，底层从 ST 读取，Memory 负责消息筛选和按当前聊天所选规则清洗，Phone 资料模块统一接入。不得访问 Memory 内部 runtime、私有设置或直接导入相邻仓库代码。先筛选并确定最近 20 条窗口，再清洗；清洗为空的消息移除，不向前补齐。沿用 Memory 现有仅对 AI 输出应用清洗的语义，用户消息与旁白不套用 AI 输出清洗规则。接口返回聊天身份、原始楼层、发送者、消息类型、清洗后正文及本次清洗规则摘要，生成时固定本次结果。未选择或停用规则时明确报告未启用清洗；所选规则不存在、读取失败或缺少公开聊天能力时明确报错，不回退为 Phone 直接读取 ST 原文。

无有效时间的纪要跳过，在生成区域简短说明跳过数量；未来纪要、未结束事件和未关联作者的纪要不进入本次输入。纪要或聊天为空时可以使用其余有效材料，写当前处境与感受；读取来源失败时明确终止，不把失败伪装为空数据。当前世界时间、作者和作者资料是生成前提。

首版采用固定取材与一次纯文本生成，不增加模型自主 SQL、工具检索、递归补充资料、语义检索或历史日记输入。输入超出模型接受范围时显示失败，不自动裁剪正文、换模型或重试。选材与提示词不能保证消除全部 OOC、幕后信息及事实偏差。

## 查看与生成流程

主屏新增「日记」。列表按实际创建顺序倒序展示，行内显示世界日期、作者和正文摘要，点击进入详情；同一世界时刻允许多篇日记。列表空时展示生成入口。

生成入口显示当前作者和读取到的世界时间。用户点击「生成日记」，应用使用 Phone 默认模型连接，流式展示正文并提供取消。没有默认连接时明确提示配置，沿用现有设置入口；不新增每篇模型选择或 ST 主连接继承规则。

正常完整生成后，应用自动新增日记并提交宿主保存，前台可进入详情；后台完成不抢焦点或跳页。无需用户额外点击保存。正文为纯文本，Prompt 引导 AI 根据人物表达和本次材料自行发挥篇幅，不设置固定字数目标；标题由作者和世界日期组成，不要求模型返回 JSON 或额外标题结构。

详情展示作者、完整日记时刻与正文，提供复制、删除和「再写一篇」。再写一篇重新读取此时的输入并新增独立条目，旧日记保持原样。删除需要一次确认；重新生成、删除或切换作者都不自动改写其他条目。

日记提供生成设置，允许修改模型请求总超时与输出 token 上限。用户已明确默认总超时为 300 秒，默认输出上限为 10240 token（2048 × 5）。这些参数作为日记应用配置保存并在后续生成时沿用，每次请求开始时固定参数副本，运行期间修改只影响下一次请求。总超时从发起模型请求开始计算，不因流式内容到达而重置；输出 token 上限作为请求参数发送，不作为正文字数要求，也不要求模型用满预算。

取消、失败、空正文及输出截断均不生成日记条目，不自动重试；用户可再次手动生成。正常完成以现有 AI 传输契约的明确结束状态判断，不以断流推定完成。

## 生命周期与保存

每次生成固定聊天、作者、资料来源与范围、连接配置和已取得的输入。运行中修改连接或 Memory 普通资料更新只影响下一次生成，不重算本次内容，也不标记旧日记失效。

Home、切换手机内应用和关闭手机窗口保留运行。Expose 明确退出日记、切换 ST 聊天、切换资料来源或范围时取消本次任务，晚到结果不写入新上下文；即使切回原聊天，也不接纳已取消任务的结果。刷新 ST 结束未完成任务，不恢复生成。单个日记应用同一时刻只运行一次生成。

生产建议将作者选择与日记存入当前聊天的 `chatMetadata.ste_phone.diary`，由日记应用拥有数据，宿主适配器负责保存。日记随聊天元数据重命名、复制或分支；复制或分支后新增和删除各自独立，继承的日记不按消息楼层裁剪，也不因聊天删消息、回退剧情或重新生成而自动撤销。实际继承行为需在专用 ST 聊天验收。

保存前必须确认仍为生成发起时的聊天；切换后的完成结果直接丢弃。只对匹配的当前聊天提交元数据保存，不支持向后台历史聊天写入。无需新增跨标签协调、修订仲裁、事务、持久任务或自动补写。

当前本地 ST 参考源码中，`saveMetadata()` 使用活动聊天保存，并存在内部捕获错误后返回的路径。实现改为通过 ST 单聊或群聊原生保存端点提交同步固定的目标与聊天快照，保留其完整性校验，不启用强制覆盖；HTTP 保存失败明确暴露，保留完整正文供复制和手动重新保存，重新保存不调用模型。请求发出后的聊天切换不修改既有请求的归属；旧聊天结果不回写新聊天页面。未保存结果在切聊天、明确退出或刷新后不恢复。该方案不增加保存队列或跨标签协调，并发宿主保存仍遵循 ST 现有文件保存语义。

## 首版边界与验收

首版不包含定时或聊天后自动生成、批量作者、正文编辑、手写日记、风格配置、日历、搜索、导入导出、Memory 写回、旧日记自动修订及按剧情回滚日记。沿用已有 App 架构、Foundation 与导航约定；资料模块接入 Memory 的公开清洗聊天读取能力，无需建设聊天 SQL 或通用任务系统。

验收至少覆盖：首次选择作者并生成完整日记，刷新后可回看；同一世界时刻再写产生独立条目；切换作者后旧条目仍保留原作者；缺少时间、人物、模型连接及资料读取错误均明确显示；空纪要与空消息正常处理；取消、超时和截断不落半篇；Home 与关手机继续，Expose 退出及聊天切换取消；资料更新不重算当前任务；保存失败可复制正文；聊天复制、重命名及分支的数据行为；Memory 或模型不可用时仍可读旧日记。

## 逐轮讨论记录

参与者为主代理与 `gpt-6.1-sol` / high 子代理。每轮由主代理提出一个主问题与推荐答案，等待 Sol 回答后继续。子代理参与产品讨论，不代表真实用户确认。

1. **谁写日记？** Sol 建议按聊天沿用单一当前作者，旧条目保留原作者，并提醒作者身份不等于知晓全部资料。主代理核对稳定身份后，将首版限定为显式选择 Memory 人物，避免新增 ST 角色映射。
2. **取哪些参考材料？** 收敛为世界状态、作者资料、关联作者的最近 5 条纪要与当前聊天最近 20 条普通消息。Sol 强调消息无剧情时间时不能承诺时间过滤，OOC 依靠提示词处理，输入范围不等于严格角色知情保证。
3. **生成后是否确认保存？** 主代理最初建议草稿确认；Sol 指出首版无编辑，建议完整生成后自动保存。最终采用「再写一篇」新增独立条目，取消和失败不保存半篇，删除入口明确可见。
4. **聊天归属和任务退出怎样简化？** 推荐聊天元数据存储、Home 与关手机继续、Expose 退出与聊天切换取消。Sol 提醒异步保存必须核实目标身份，不能仅捕获元数据对象就认为可以安全向旧聊天保存。
5. **边界场景压力测试。** 核对 ST 保存源码后明确宿主落盘确认的限制；以同日多篇、资料更新、聊天切换、刷新和分支检查范围。Sol 确认可以形成待审阅草案，补充取消后切回原聊天也不能接纳迟到结果，以及保存调用前检查身份仍不足以证明异步保存期间目标固定。后者列入实施验证项。

用户后续修订：生成总超时和输出 token 上限开放设置，默认值分别为 300 秒和 10240 token；正文篇幅由 Prompt 引导 AI 自行发挥，移除原先建议的 400–800 汉字目标。此项已按用户明确意见更新，其余讨论建议仍待审阅。

## 依据与实施待核验事项

仓库依据为 README、CONTEXT、架构文档、公共资料文档及 ADR 0005/0006。已核对现有 `PhoneBackground` 只含展示用人物、纪要和物品；世界状态与纪要时间应通过已有标准视图读取，不能假设其已在背景快照中。Core 当前仅提供聊天身份与变化通知，聊天正文读取仍需补充到资料能力。

本轮查阅本地 tmp 中的 ST 参考源码确认 `getContext()` 提供聊天消息、聊天元数据与保存入口；参考资源只用于调研，已跟踪代码不得依赖该目录。不将参考源码行为当成所有 ST 版本的保证。当前方案沿用既有模块决策，未产生需要新增 ADR 的难逆转架构取舍。
